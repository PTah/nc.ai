# NotCursor.ai

AI-агент для работы с кодом в отдельном окне: чат, дерево проекта, редактор и настоящий терминал.
Написан на **Wails v2 (Go) + React/TypeScript** — то есть поверх системного WebView, без Electron и
без рантайма на 200 МБ рядом с exe.

Агент читает и правит файлы в вашем проекте, запускает команды, коммитит и пушит через системный
`git`, ходит по SSH по ключам из `~/.ssh`. Ключи провайдеров лежат в системном хранилище (macOS
Keychain / Windows Credential Manager), история чатов — локально. Наружу уходит только запрос к
тому провайдеру LLM, которого вы выбрали сами.

**Версия:** `0.7.6` · **На выходе:** `build/bin/NotCursor.exe` (Windows) и `build/bin/NotCursor.app` (macOS)

## Быстрый старт

Этот раздел — для тех, кто хочет **собрать приложение сам из исходников** (разработка, свой хост,
кастомная сборка). Если вам просто нужен рабочий NotCursor.ai — не компилируйте ничего: возьмите
готовую сборку из **раздела релизов** (папка `docs/releases/`, там же инструкция по запуску). Всё, что
ниже, можно спокойно пропустить.

Что нужно поставить заранее:

- **Go** 1.26 (`go.mod` требует `go 1.26.0`) и **Node.js** с npm;
- **Wails CLI** версии 2.15.0 — `go install github.com/wailsapp/wails/v2/cmd/wails@v2.15.0`
  (чтобы `wails` нашёлся в `PATH`: `%USERPROFILE%\go\bin` на Windows, `~/go/bin` на macOS);
- Windows: WebView2 Runtime (в актуальных сборках Windows уже стоит). macOS: Xcode Command Line
  Tools — нужны и для сборки, и для ad-hoc подписи `.app`.

Дальше из корня репозитория:

```bash
cd frontend && npm install && cd ..
wails dev
```

Откроется окно NotCursor. Идёте в **Settings → Provider**, вставляете ключ DeepSeek — или выбираете
провайдер Local, если Ollama/LM Studio уже крутятся рядом. Без ключа окно откроется, но чат отвечать
не будет.

Проверить, что код собирается и тесты зелёные:

```bash
go test ./...
```

### Сборка бинаря

Windows:

```powershell
.\build.ps1                    # собрать и перезапустить NotCursor.exe
.\build.ps1 -NoRestart         # только собрать
.\build.ps1 -CopyTo D:\Share   # собрать и скопировать exe в папку раздачи
```

macOS (собирается только на macOS-хосте; скрипт сам делает ad-hoc codesign):

```bash
./build.sh                     # собрать, заменить /Applications/NotCursor.app и перезапустить
./build.sh --no-restart        # только собрать
./build.sh --universal         # fat binary arm64 + amd64
./build.sh --no-install        # не трогать установленную копию
./build.sh --install-to ~/Apps # ставить не в /Applications, а в свою папку
./build.sh --copy-to ~/Share   # вдобавок скопировать .app в папку раздачи
```

Скрипт собирает `build/bin/NotCursor.app`, делает ad-hoc подпись, **заменяет**
`/Applications/NotCursor.app` свежим бандлом (старый процесс при этом закрывается) и запускает
приложение уже из `/Applications`. Поэтому значок в Dock/Spotlight и «Программы» всегда указывают на
последний билд — отдельного установщика нет, но и вручную копировать `.app` больше не нужно.
Целевую папку можно изменить через `--install-to DIR` или переменную `NC_INSTALL_DIR`.

## Провайдеры

Переключение — **Settings → Provider**.

| Провайдер | Модели | Что стоит знать |
|---|---|---|
| DeepSeek | `deepseek-flash`; legacy `deepseek-v4-flash`, `…-vision-exp` и `deepseek-v4-pro` роутятся на неё | OpenAI-compatible API, авто-выбор модели |
| Z.ai | `glm-4.5…5.3` (flash / pro / vision) | список моделей и баланс показываются прямо в Settings |
| OpenRouter | любой `openrouter/…` | свой ключ и endpoint |
| Qwen (DashScope) | `qwen-max` / `qwen-plus` / `qwen-turbo`, `qwen3-coder-*`, `qwen-vl-*` | Alibaba Cloud Model Studio, OpenAI-compatible; регион intl / cn |
| Local | всё, что вернёт `/models` — Ollama, LM Studio, vLLM, llama.cpp | по умолчанию `http://127.0.0.1:11434/v1`, ключ не обязателен |

- Авто-выбор модели идёт по цепочке flash → legacy `deepseek-v4-pro` (пока он жив) → мультимодальная
  flash. После 14.09.2026 12:00 Beijing `v4-pro` уезжает из списка, и расчёт идёт по `deepseek-flash`.
- Ошибки провайдеров переводятся в понятный текст: `402` → «Пополните баланс…», `429` → «лимит
  запросов…» — вместо голого JSON.
- Кнопка **↻ Models** перечитывает список моделей у активного провайдера. DeepSeek тоже ходит в
  `GET /models`, а не берёт список из кода.
- Ключи не пишутся в `settings.json`: macOS Keychain, Windows Credential Manager, на Linux — файл с
  правами `0600`. Стираются кнопками Clear key / Clear all keys.

## Агентский цикл

Запрос → thinking / tool calls по протоколам из `docs/exchange-protocols/` → результаты инструментов
→ следующий шаг, пока агент не закончит.

- Лимит шагов за один запрос — **Settings → Agent**: по умолчанию 120, галочка «без ограничения»
  снимает жёсткий предел (агент не останавливается, а после порога «Предупреждать после N» пишет,
  что работа продолжается). Когда жёсткий лимит всё-таки кончается, агент делает soft wrap-up без
  инструментов: отвечает тем, что успел выяснить.
- Во время работы агент присылает **этапы**: шаг x/y, сколько прошло, что сделано и что сейчас.
  Карточки «Этап» в ленте и живой статус над полем ввода — **по запросу** («показывай промежуточные
  результаты», «по этапам», «что делаешь») либо автоматически, когда агент молчит без вывода
  результата больше двух минут.
- Вопросы, набранные во время работы агента, **встают в очередь этого чата** (своя очередь у каждого
  проекта) и панель очереди всегда видна над полем ввода. `Send now` — прервать текущий ответ и отправить.
- Рассуждения модели свёрнуты под «Thinking…»: раскрыть — кликом, по умолчанию их не видно.
- Reconnect: сетевые сбои и ответы `429` / `1302` / `1305` повторяются с backoff. Если и это не
  помогло, в шапке появляется кнопка **Reconnect**.
- Компакция: результаты старых инструментов сворачиваются в `[compacted] …`, полными остаются
  последние три — иначе длинный чат упирается в лимит контекста. Компакция идёт между ходами агента.
- Prefix-cache: стабильные system и turn-rules держатся в начале промпта, чтобы попадать в кэш
  провайдера. Рядом с расходами в шапке есть чип `cache N%` — это попадания по **текущему** чату;
  полная разбивка (строки `chat cache … hit / … miss (N%)` и `total cache … hit / … miss (N%)`)
  появляется во всплывающей подсказке при наведении на чип. Пока провайдер не вернул ни одного
  cache-токена, чип показывает `cache —`, а в подсказке процентов нет — только нули.
- Сообщение, отправленное во время прогона, встаёт в очередь и уходит после текущего ответа.
- **Сеть и обрывы связи** (Settings → Network): **HTTP protocol (LLM)** переключает протокол к
  провайдерам — `Auto (HTTP/2)` или `HTTP/1.1` (h2 выключен: помогает, когда CDN или роутер с обходом
  блокировок рвут длинный поток, «connection reset by peer» в середине ответа). **HTTP/2 keepalive**
  (по умолчанию 20 сек) шлёт PING после полной тишины, чтобы соединение не засыпало в NAT/DPI, а
  мёртвый поток был виден сразу. Рядом — **Reconnect attempts** (сколько раз переподключаться после
  обрыва, по умолчанию 3) и **Reconnect budget, sec** (сколько суммарно ждать серию повторов, по
  умолчанию 180), а также счётчик обрывов за запуск с текстом последней ошибки и кнопкой сброса.
- **Watchdog «затыка»** (Settings → Agent, «Обрывать зависший шаг через, мин»): если шаг не подаёт
  признаков жизни — ни ответа модели, ни начала/конца инструмента, ни дельт стрима — дольше указанного
  времени (по умолчанию 10 минут), прогон **принудительно обрывается**, а в ленту уходит разбор: на каком
  шаге встали, сколько ждали, в какой фазе (ждём ответ модели или висит инструмент), какая модель и
  сколько инструментов уже отработало, плюс что с этим делать. Галочка «не обрывать зависший шаг»
  отключает контроль.

## Инструменты

| Tool | Что делает |
|---|---|
| `read_file` / `write_file` / `apply_patch` / `delete_file` / `move_file` | чтение (с номерами строк), запись, патч, удаление, rename внутри песочницы |
| `list_dir` / `find_files` / `glob` / `grep` | обход каталогов, поиск по нечёткому имени, по glob (`**/*.go`), по содержимому (regex как в ripgrep) |
| `run_terminal` / `command_status` | shell-команды: свой `cwd`, фоновый режим (`is_background`) |
| `todo_write` / `ask_user` / `read_lints` | список задач, вопрос пользователю, `go vet` по изменённым файлам |
| `web_search` / `fetch_url` | веб — с SSRF-guard: LAN, loopback и metadata-адреса закрыты |
| `git_*` | status / diff / log / commit / push через **системный `git`** |
| `ssh_*` | exec и генерация ключей, ключи берутся из **`~/.ssh`** |

Пути считаются от корня проекта и выше него не выходят. Если `read_file` получил несуществующий
путь, он подсказывает похожие файлы из той же папки.

## Интерфейс чата

- **Plan / Act** в шапке. Plan — агент только читает и планирует, без правок и shell-команд.
- **Проекты** — кнопка **Project ▾** в левой панели: **Open project…** открывает существующую папку,
  **Create project…** создаёт новую папку проекта в выбранном месте и сразу открывает её (поле «Где
  создать» подставляется из прошлого раза, «Обзор…» — выбор папки). Имя папки не должно содержать
  разделители пути и символы `< > : " | ? *`, повторно создать уже существующую папку нельзя — только
  открыть.
- **Clone repository…** клонирует репозиторий в выбранную папку и сразу открывает его как проект.
  Способ доступа выбирается сам: если SSH настроен (ключ в `~/.ssh`, порт и `IdentityFile` берутся
  из `~/.ssh/config`) и хост отвечает — клонируем по SSH, иначе по HTTPS. Поддерживаются ссылки
  `ssh://git@host:port/path`, `git@host:path`, `https://host/path` и локальные пути/`file://`.
  Папка получает имя репозитория; её путь виден в диалоге до нажатия «Клонировать». Если доступа нет
  ни по SSH, ни по HTTPS, в диалоге показывается ошибка с обеими попытками и подсказкой, что проверить
  (ключ в аккаунте / токен для HTTPS и права на репозиторий). Клонирование ждёт до 5 минут.
- Клик по файлу в дереве открывает редактор, а не вываливает содержимое в чат; заодно файл попадает
  в IDE-контекст агента.
- После вызова `todo_write` над тредом висит список задач. **ПКМ по блоку ToDo или по отдельному
  пункту** открывает меню: «Убрать пункт», «Убрать выполненные», «Скрыть блок в чате» (план у агента
  остаётся) и «Убрать ToDo целиком» (список чистится, блок скрывается). Убранные вручную пункты не
  воскресают при следующем `todo_write` с merge — они вернутся только с новым планом (merge=false).
- Thinking-блоки и завершённые tool-вызовы после финального ответа схлопываются в один блок
  **Thinking & Explored**.
- **Вкладки чатов**: `+` создаёт новую сессию, двойной клик по вкладке — переименование, старые
  сессии никуда не пропадают.
- **Архив**: кнопка в шапке чата переносит сессию в `%APPDATA%/NotCursor/chat_archive/<имя>.json`.
  Список архивов открывается из UI, архивный чат смотрится read-only и в активные вкладки не
  подмешивается.
- **Поиск по чату** — **Ctrl+F**: панель со счётчиком, `↑` / `↓` (и `F3`), выход по `Esc` или
  повторному **Ctrl+F**. Считается только видимый текст: содержимое свёрнутых Thinking / tool-блоков
  в счётчик не попадает.
- Деньги: в шапке видно `chat $0.0043 · total $0.1231 · cache 42%` (у Z.ai и OpenRouter рядом ещё и
  баланс). Наведение курсора на этот блок раскрывает расшифровку: токены in/out по чату и всего, а
  также chat и total cache в виде `… hit / … miss (N%)`. Peak / off-peak DeepSeek учитывается, прайс
  подтягивается сам.
- Прайсы проверяются автоматически: DeepSeek и OpenRouter — раз в сутки после 13:05 Beijing, z.ai —
  раз в неделю. Результат приходит в чат системным сообщением.
- История чатов хранится по проектам в `%APPDATA%/NotCursor/chats/` (на macOS — в
  `~/Library/Application Support/NotCursor/`).

## Правила Cursor

Правила собираются и подмешиваются к системному промпту:

- глобально: `~/.cursor/rules/*.mdc|md` (рекурсивно), `~/.cursorrules`, `AGENTS.md`;
- в проекте: `<project>/.cursor/rules/*` (рекурсивно), `<project>/.cursorrules`.

В **Settings → Cursor Rules** видно, что загрузилось, и есть кнопка **Reload**.

## Терминал

Внизу есть **панель терминала** (открывается по **Ctrl+Shift+T**; настройки приложения, в том числе
выбор shell, — отдельным окном по **Ctrl+Shift+S**). Внутри панели живут **два разных режима запуска
команд**, и путать их не стоит — от режима зависит, что вообще сработает.

**1. Интерактивная сессия — как обычный терминал в системе.** Это настоящий PTY: ConPTY на Windows,
pty на macOS и Linux. Shell берётся из **Settings → Shell** (пусто — авто: PowerShell 7 или 5 на
Windows, `$SHELL` на macOS/Linux), стартовая папка — корень активного проекта. Печатать можно прямо в
область вывода: работают history, `cd`, Ctrl+C, vim и top, ssh с вводом пароля, прогресс-бары.
`TERM=xterm-256color`, `COLORTERM=truecolor`, размер окна подтягивается за панелью. Пока сессия жива,
её состояние (текущая папка, переменные, активированный venv) сохраняется между командами. Когда
процесс завершился, в выводе появляется `[shell exited]`.

**2. One-shot — «одна команда, один процесс».** Поле ввода рядом с кнопкой **Run** (плейсхолдер
`oneshot: date`) запускает одну команду отдельным процессом: PowerShell `-Command`, POSIX-shell `-lc`,
cmd `/C`. Рабочая папка — корень проекта, stdin закрыт, вывод идёт через пайпы, таймаут 60 секунд.
Результат дописывается в тот же xterm строками `> команда` … `[exit N]`, поле очищается.

Разница на практике:

| | Интерактивная сессия | One-shot (Run) |
|---|---|---|
| Состояние (`cd`, переменные, venv) между командами | сохраняется | **не** сохраняется — каждый Run = новый процесс |
| Интерактив (vim, пароль ssh, `git rebase -i`) | работает | **не** работает |
| Профиль shell (PATH, алиасы, venv) | загружается | **не** загружается |
| Долгие процессы (dev-сервер, watcher) | не для этого | не для этого — только агентский `run_terminal` с `is_background` |

Отсюда главная практическая заминка: если команда в интерактивной сессии проходит, а через **Run**
падает с `[exit 1]` и пустым выводом — ей не хватило `PATH` / алиасов / venv из вашего профиля
(one-shot запускается без профиля). Указывайте полный путь к бинарю или запускайте команду в
интерактивной сессии.

## Безопасность

- Секреты не уезжают в модель: `read_file` по `.env*`, `id_rsa`, `*.pem`, `*.key`, `*secret*`
  возвращает заглушку, значения `KEY=…` / `TOKEN=…` маскируются в `***`.
- SSH: сверка с `~/.ssh/known_hosts`, TOFU при первой встрече. Изменился ключ хоста — соединение
  отклоняется.
- `git_commit` стейджит только изменения уже отслеживаемых файлов (`git add -u`), новые файлы
  случайно не улетят.
- JSON чатов и настроек пишется атомарно (temp + rename) с ротационной копией `.bak`.

## Скриншоты

UI читает картинку из файла или буфера обмена и отдаёт её как `data:image/png;base64,…`, backend
собирает user-сообщение с `image_url`, дальше запрос идёт в vision-модель и обычный tool loop.

## Settings

- **Provider** — DeepSeek / Z.ai / OpenRouter / Qwen (DashScope) / Local (несколько LAN-серверов): ключ, модель, base URL.
  Для Custom: режим Lite, Auto-models, индикатор скорости рядом с Rules — см. [docs/local-models-ru.md](docs/local-models-ru.md).
- **Agent** — лимит шагов, Plan mode, подтверждение опасных инструментов.
- **Interface** — тема (Dark / Light), показ терминала, дерева и панели настроек.
- **Shell** — путь к shell для интерактивного терминала и кнопка «Авто (обнаружить)».
- **Cursor Rules** — список загруженных правил и reload.
- **Git & SSH** — логинов в UI нет, используется системный `git` и `~/.ssh`.

Данные приложения: `%APPDATA%\NotCursor` (Windows), `~/Library/Application Support/NotCursor` (macOS).

## Коммит и push

```powershell
.\commit.ps1 "feat: описание изменений"
```

```bash
./commit.sh "feat: описание изменений"
```

Оба скрипта делают `git add -A` и `git push` в тот remote, который прописан у ветки. Это удобно,
когда дерево чистое, и неприятно, когда рядом лежит что-то лишнее.

## Релизы

Релиз на GitHub — это тег `vX.Y.Z` и по файлу на платформу:

| Платформа | Файл |
|---|---|
| Windows x64 | `nc.ai-X.Y.Z-windows-amd64.zip` |
| macOS arm64 | `nc.ai-X.Y.Z-macos-arm64.zip` |
| macOS universal | `nc.ai-X.Y.Z-macos-universal.zip` |

Рядом с **каждым** архивом кладём подпись `<имя архива>.sha256` — sha256 главного исполняемого файла
**внутри** архива (в zip это `NotCursor.exe`, в macOS-архиве `NotCursor.app/Contents/MacOS/NotCursor`):

```
sha256sum NotCursor.exe > nc.ai-0.6.30-windows-amd64.zip.sha256
shasum -a 256 NotCursor.app/Contents/MacOS/NotCursor > nc.ai-0.6.30-macos-arm64.zip.sha256
```

Зачем: при старте приложение сверяет хеш своей сборки с подписью из последнего релиза. Поэтому видно
не только «вышла версия новее», но и **перезаливка файла под тем же номером версии** — по одним лишь
цифрам такая замена осталась бы незамеченной. Если подписи нет, проверка работает как раньше — по
номеру версии.
