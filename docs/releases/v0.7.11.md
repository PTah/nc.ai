## NotCursor 0.7.11 — nc.ai

Продолжение мультипроектной истории: сначала ответы уезжали в чужой проект, теперь нашёлся второй
механизм — **транскрипт** чата одного проекта затирал чат другого.

### Что было

`restoreChat(projectPath)` собирал состояние из **двух разных источников**:

```tsx
const bundle = await ListChatSessions()      // ← бандл АКТИВНОГО проекта бэкенда (аргумента нет)
const activeId = bundle?.activeId            // ← id сессии из этого бандла
const raw = await LoadChat(projectPath)      // ← транскрипт ЗАПРАШИВАЕМОГО проекта
setItemsBySession(prev => ({...prev, [activeId]: chatItems}))
```

`ListChatSessions()` не принимает проект и отдаёт бандл того проекта, который «активен» на бэкенде,
а `LoadChat` — по переданному пути. Пока эти два состояния расходятся (переключение проекта —
несколько асинхронных вызовов, между ними окно), транскрипт одного проекта вешался на id сессии
другого. Дальше автосохранение (300 мс) аккуратно записывало эту кашу на диск — прямо в файл
чужого проекта.

Так чат `buy-sum` получил транскрипт `nc.ai` целиком, один в один по индексам:

```
buy-sum · сессия 918cd341 · items=837
  [760] user      : чини. затем коммит пуш, релиз в гитхаб, и затем рестарт приложения
  [809] reasoning : All green. Now: 1. Build the exe. 2. Commit + push…
  [822] reasoning : артефакты релиза собраны, zip и sha256 в релизе…
  [830] assistant : Готово: починил, закоммитил, запушил, выпустил релиз и зарядил рестарт.
```

### Как починено

- **Один источник для пары «сессия + транскрипт».** Новый RPC `LoadChatTranscript(projectPath)`
  возвращает `{sessionId, project, itemsJson}` — id и элементы приходят из **одного** вызова, поэтому
  транскрипт физически не может быть повешен на чужую сессию. `restoreChat` теперь использует его,
  а `ListChatSessions(projectPath)` стал принимать проект явно (раньше аргумента не было вовсе).
- **Сохранение только по ключу сессии.** Все пути сохранения (автосохранение, смена чата/проекта,
  создание вкладки, закрытие проекта, завершение прогона, `beforeunload`) идут через
  `persistSession(sessionId)`, который берёт элементы **из `itemsBySessionRef[sessionId]`**. Передать
  «элементы со стороны», как раньше (`SaveChatSession(activeSessionId, items)`), больше нельзя.
- **Диагностика на будущее:** если входящий транскрипт упоминает вопрос, которого нет в истории
  сессии, приложение пишет в `agent.log` строку `chat save: … cross-project write?` — перекрёстная
  запись перестанет быть невидимой.

### Проверка руками

1. Запустить агента в проекте A, переключиться в B, задать там второй вопрос.
2. Убедиться, что в чате B нет хвоста чата A (ни в транскрипте, ни в истории модели), а вкладки
   обоих проектов показывают свои вопросы.
3. Вернуться в A — ответ A на месте, чат A не тронут.

### Установка (Windows 10/11, x64)

1. Скачать `nc.ai-0.7.11-windows-amd64.zip` и распаковать в любую папку.
2. Запустить `NotCursor.exe`.
3. Дальше обновления — кнопкой из приложения.
