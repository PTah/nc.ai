## NotCursor 0.9.0 — nc.ai

### Проблема, которую закрывает релиз

Агент каждую сессию заново выяснял, «где что лежит»: `grep` → `read_file` → `grep`, потому что
между прогонами у модели нет никакой памяти, кроме того, что лежит в текущем промпте. В промпт
попадало только дерево имён файлов — по строке `internal/netx/ndis.go` невозможно понять, что
внутри разбор hex от Windows NDIS. Отсюда «сейчас посмотрю, где лежит…» на каждой задаче.

Теперь у агента четыре источника знаний о проекте, от дешёвого к дорогому.

### 1. Карта проекта в промпте (L0)

Второе сообщение после system prompt (`<project_map>`) начинается с brief:

- корень и go-модуль, число файлов/строк/символов;
- go-пакеты по объёму: `internal/agent(agent,30f), internal/config(config,8f), …`;
- точки входа: `cmd/*/main.go`, `package main` c `func main`;
- крупнейшие файлы — где «мясо»;
- не-Go код по каталогам и языкам, документация.

Дерево путей остаётся ниже, в `<workspace_tree>`, — как буквальный список. Бюджет: 1600 байт
(700 на LocalLite), обрезка по границе строки, чтобы не рвать фразу пополам.

### 2. Индекс символов проекта (L1)

Пакет `internal/projindex`:

| Что | Как |
|---|---|
| Go | `go/parser` + `go/ast`: функции, методы с приёмником, типы, struct/interface, const/var, первая строка doc-комментария, `file:line` |
| Остальное | regex по правилам для ts/tsx/js/jsx, vue/svelte, py, cs, ps1/psm1, sh/bash/zsh, rs, java/kt/scala, rb |
| Кэш | `size + mtime` на файл: изменился один файл — перепарсивается один файл; память процесса + JSON в кэш-каталоге ОС (версия кэша сбрасывает устаревшее) |
| Границы | `node_modules`, `vendor`, `dist`, `build`, `.git`, бинарники — вне индекса; файлы > 1 МБ не парсятся, на огромных репозиториях парсинг ограничен |

Инструменты (только чтение, параллелятся):

- `find_symbol(name, path?, limit?)` — поиск объявления по имени, подстрока или regex;
- `project_search(query, path?, limit?)` — скоринг по именам, doc-комментариям и путям: «где
  обработка online/offline» отвечается списком `file:line` без открытия файлов.

Один такой вызов заменяет цепочку `grep` + несколько `read_file`. Файл всё равно читается перед
правкой — это правило промпта, а не ограничение инструмента.

### 3. Память фактов проекта (L2)

Пакет `internal/projmem`, инструменты `remember` / `recall` / `forget`:

- заметка = одна строка факта + пути, к которым она относится;
- хранение вне репозитория (config-каталог ОС, ключ — абсолютный путь проекта): память не попадает
  в git и не требует прав на запись в проект;
- повторная запись того же факта обновляет заметку и сливает пути, копии не плодятся; лимит 300
  заметок, старые вытесняются;
- **честное протухание**: если файл из заметки изменён после её записи, `recall` и блок
  `<project_memory>` помечают заметку как «файл изменён после записи, проверь». Память не
  выдаётся за истину задним числом;
- `<project_memory>` — снимок на старте прогона (запись в середине прогона не сдвигает
  prefix-cache), бюджет 1200 байт, 500 на LocalLite.

### 4. Поиск по истории чатов проекта (L3)

Пакет `internal/history`, инструмент `history_search(query, limit?)`:

- ищет сообщения user/assistant в живых чатах и в архиве, **строго по текущему проекту**;
- скоринг по токенам запроса + бонус за точную фразу и за совпадение в названии чата;
- не больше двух хитов на чат, снипет ±180 символов вокруг первого совпадения, обрезка по границе
  UTF-8;
- «мы это обсуждали» и «почему так решили» отвечаются из прошлых чатов, а не пересказываются
  заново.

### Интерфейс

«Авто (по настройкам)» и «Развернуть всё» больше не живут в ленте ответов: они закреплены в полосе
ввода рядом с Attach и подсказкой «Enter — отправить · картинки → vision». Раньше они стояли в
потоке последним блоком и уезжали вместе с прокруткой — то вверх, то вниз.

### Что это не решает

«Никогда не искать» невозможно: код меняется, а весов вашего проекта у модели нет. Цель другая —
первый шаг точный, а не восьмой. Если brief, индекс и память промахнулись, `grep` остаётся, и это
правильно.

### Проверка

- `go build ./...` и `go vet ./...` — без ошибок;
- `go test ./...` — зелёные, включая новые пакеты `internal/projindex`, `internal/projmem`,
  `internal/history`;
- `npm --prefix frontend run build` (tsc + vite) — без ошибок;
- прогон индекса на самом репозитории nc.ai: 338 файлов, 3208 символов, 54.9k строк — brief
  укладывается в 886 байт из 1600.

### Установка (Windows 10/11, x64)

1. Скачать `nc.ai-0.9.0-windows-amd64.zip`, распаковать, запустить `NotCursor.exe`.
2. Ключи провайдеров — **Settings → Providers**.

### Установка (macOS 12+, Apple Silicon и Intel)

1. Скачать `nc.ai-0.9.0-macos-*.zip`, распаковать.
2. Перенести `NotCursor.app` в «Программы», запустить (ad-hoc подпись: правый клик → «Открыть»).
