## NotCursor 0.9.4 — nc.ai

### Зачем

Жалоба звучала так: «пишу сообщение, оно уходит в очередь, в очереди жму „Отправить“ —
не уходит; жму Stop в верхней панели — тоже не реагирует». Виновато было состояние
«чат занят»: оно хранилось **отдельной картой** от счётчика дорожек прогонов.

- «Занято» ставилось в одном месте (`runAgent`), а снималось в другом — внутри
  обновления счётчика (`finishRunLane`). Обновление состояния изнутри другого
  обновления React может не применить: счётчик дорожек уже 0, а карта «занято» —
  всё ещё `true`.
- Пока карта врала, вопрос из очереди не уходил никогда (дренаж ждёт «не занято»),
  а Stop было нечего останавливать: прогон на бэкенде давно завершён, отменять нечего,
  и в UI не приходило ни одного события. Со стороны — «кнопки не работают».

### Что изменилось

- **Один источник правды.** `busy` — производная от `runCountBySession` (`useMemo`),
  отдельной карты `busyBySession` больше нет. Состояние «занято» физически не может
  разойтись со счётчиком дорожек; вложенный `setState` из обновления удалён.
- **Сверка с бэкендом (watchdog).** Пока на экране есть «занятые» чаты, раз в 3 с
  читается `ActiveRuns()` (биндинг уже был, теперь используется). Две подряд сверки
  «прогонов нет» (≈6 с) — значит событие завершения потеряно: дорожки закрываются,
  лента собирается, в чат пишется объяснение, очередь идёт дальше.
- **Stop работает всегда, когда он активен.** Кнопка вызывает `StopAgentSession`,
  затем сразу сверяется с бэкендом: если работы уже нет — состояние чинится и очередь
  отпускается; если прогон ещё жив — в чате появляется «⏹ Останавливаю прогон…».
- **«Отправить» на карточке очереди больше не молчит.** Если «занято» оказалось
  фантомным, вопрос уходит сразу, без ожидания. Если чат правда занят — один раз
  пишется подсказка «уйдёт сразу после текущего ответа» (повторные клики не спамят).
- `flushQueue` при ответе «busy» тоже запускает сверку, поэтому очередь не может
  встать из-за остатка потерянного события.

### Проверка

- `npx tsc --noEmit` (frontend) — чисто.
- `go vet ./...`, `go test ./...` — без новых падений (см. «Ограничения»).
- `./build.sh` — сборка macOS 0.9.4, версия в `About` и в бандле совпадает с тегом.

### Ограничения

- Сверка не умеет отличать «прогон жив, но молчит» от «прогон жив и работает»: она
  смотрит только наличие прогона в `ActiveRuns`, поэтому живой прогон не закрывается
  никогда — watchdog трогает только фантомы.
- `internal/tools` `TestCheckCommandScope` продолжает падать на macOS (ожидает
  Windows-пути); падение было до этого релиза и к нему не относится.
