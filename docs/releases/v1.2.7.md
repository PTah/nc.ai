## NotCursor 1.2.7 — nc.ai

### Git-хостинги: несколько, со своими именами, без лишних логинов

В 1.2.6 настройки выглядели как три фиксированных пункта с токенами. Это неправильно: на машине уже
настроены SSH-ключи и credential helper, а «куда пушить» — это про **имена хостингов**, свои на каждой
машине: `Home`, `work`, `github`.

Теперь в Settings → Агент и MCP → **«Git-хостинги»** список записей, и у каждой:

| Поле | Смысл |
|---|---|
| `name` | имя для команды: «Выложи на Home / на гитхаб / на work» |
| `kind` | Gitea или GitHub |
| `baseUrl` | адрес сервера для API и https-клона (`https://git.example.com`) |
| `sshBase` | ssh-адрес: `git@git.example.com:2222` или `ssh://git@host:2222` |
| `owner` | владелец/организация по умолчанию |
| «создавать push-ем» | Gitea создаст репозиторий от первого `git push` — токен не нужен |
| «по умолчанию» | куда выкладывать, если в команде хостинг не назван |

**Токен — только для создания по API** и только если «создавать push-ем» не включено. Коммиты и пуши
идут обычным `git` на машине: SSH-ключи, `~/.ssh/config`, credential helper — всё, что уже настроено,
используется как есть. Токен хранится в системном хранилище секретов, в `settings.json` его нет.

Если в команде назван хостинг, которого нет в списке, агент возьмёт хостинг «по умолчанию» и скажет об
этом в ответе; если списка нет вовсе — проект останется локальным с готовым репозиторием и первым
коммитом.

### Адреса репозитория

`internal/gitrepo.Host.RepoURLs` собирает адреса из настроек: для GitHub — `git@github.com:<owner>/<repo>.git`,
для Gitea — `ssh://git@host:2222/<owner>/<repo>.git` при указанном порте (scp-форма с портом не работает),
иначе `git@host:<owner>/<repo>.git`; https-вариант — `baseUrl/<owner>/<repo>.git`. Предпочтение отдаётся
ssh (работает по уже настроенным ключам), https остаётся запасным.
