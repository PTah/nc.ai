# NotCursor 1.2.1

Исправлен баг, из-за которого после возврата в окно приложения чат выглядел пустым — как будто
никаких заданий не было. История при этом **не терялась**: в файле проекта лежали все 630 элементов
диалога (проверено на живом инциденте). Ломалось только отображение.

## Что происходило

1. `frontend/src/webviewRecover.ts` после **2 минут** в фоне безусловно делал `WindowReloadApp` —
   «на всякий случай», потому что WebView2 иногда оставляет белое полотно. Перезагрузка стирает
   состояние React: сессии, элементы чата, черновики.
2. Дальше восстановление шло одной цепочкой `ListChatSessions → LoadChatTranscript → JSON.parse →
   applyUsageStats`, и **любой** её сбой уходил в общий `catch`, который делал
   `setItemsBySession({})`, `setSessions([])`, `setActiveSessionId('')` — пустые вкладки и пустой чат.
   В `agent.log` при этом не оставалось ни строки.
3. Если транскрипт приходил пустым, UI показывал заглушку «История пуста — задайте задачу», хотя
   `history` сессии на диске была полной. Сохранение пустого транскрипта поверх живой истории
   блокировалось (`SaveChatSession`), поэтому данные уцелели.

## Что исправлено

- **Перезагрузка WebView только при реально пустом экране.** Убран безусловный soft-reload по
  таймеру: после возврата в окно делаем kick композитора, ждём 600 мс и перезагружаем, только если
  `#root` действительно пуст. Долгий уход в другое приложение больше не перезагружает UI.
- **Восстановление чата не разрушает состояние.** Ошибка больше не обнуляет вкладки и чат: показываем
  системное сообщение, пишем строку `[ui] restore-chat: …` в `agent.log` (новый `App.LogUIError`) и
  повторяем попытку автоматически (до трёх раз с нарастающей паузой).
- **Самовосстановление из истории.** В `ChatTranscript` добавлено `historyLen`; если транскрипт пуст,
  а история жива, UI пересобирает реплики через новый `App.RestoreItemsFromHistory` (ядро —
  `chatstore.ItemsFromHistory`) и помечает чат строкой «↩ Чат восстановлен из истории сессии».
  То же сделано при переключении вкладок (`switchSession`).
- **Статистика и каталог моделей больше не роняют восстановление:** `applyUsageStats` вызывается
  отдельно, со своим `catch` и записью в лог.

## Проверки

- `internal/chatstore/rebuild_test.go`: пересборка реплик из истории, отбрасывание пустых и
  инструментальных сообщений.
- `go build ./...`, `go test ./internal/chatstore ./internal/agent ./internal/llm/providers/anthropic ./internal/tools`,
  `tsc --noEmit`, `wails build` — зелёные.

## Заодно в этом же релизе

- **Anthropic: `thinking` больше не отправляется всем подряд.** Агент всегда шлёт
  `Thinking: {"type":"enabled"}`, а адаптер транслировал это в API без проверок — на claude-3.x и на
  чужих anthropic-совместимых эндпоинтах это 400 на каждом запросе. Теперь параметр уходит только
  для моделей с extended thinking (3.7-sonnet, 4.x), бюджет зажат в `[1024, modelMaxOutput-1024]`,
  а `max_tokens` поднимается под бюджет.
- **`internal/tools` снова зелёный на Windows:** `TestMultiRootScopeKnowsAllFolders` брал
  `/usr/local/...` (на Windows не абсолютный путь) — тест собирает путь вне корней по правилам ОС,
  и проверка «команда пишет вне проекта» снова срабатывает.

## Что осталось

- Инцидент воспроизводился на глаз (не автоматическим тестом): нужен сценарий «увести окно в фон на
  2+ минуты и вернуться». Ручная проверка — после установки 1.2.1.
- Черновики (`composer-drafts.json`) в том инциденте обнулились (777 → 2 байта) в момент старта UI.
  Отдельного фикса в этом релизе нет — при следующем воспроизведении смотреть `[ui]`-строки в логе.
