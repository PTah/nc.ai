## Anthropic: подпись thinking-блока ходит по кругу

Раньше `signature` читалась из ответа и терялась. Теперь блок рассуждений возвращается в API
байт-в-байт при продолжении tool-loop того же хода:

- `llm.ThinkingBlock` (`thinking` + `signature`) в `llm.Message`, только в памяти прогона — другим
  провайдерам поле чуждо, на диск не пишется;
- `reasoning` включается по `req.Thinking` (`{"type":"enabled","budget_tokens":N}`), `temperature`
  при этом снимается, `max_tokens` гарантированно больше бюджета;
- если рассуждение выключено, блоки не отправляются (API их не примет) — тест это стережёт;
- поток: `signature_delta` собирается в тот же блок;
- `compact`/`escalate` чистят блоки вместе с `reasoning_content`.

Файлы: `internal/llm/providers/anthropic/adapter.go`, `stream.go`, `internal/llm/types.go`,
тесты `anthropic/thinking_test.go`.

## Подагенты параллельно

`Settings → Agent → Subagents in parallel` (1–8, по умолчанию 1 — по очереди).
Несколько `task`-вызовов в одном ответе модели идут одновременно, лимит одновременности держит
семафор, общий лимит «подагентов за прогон» остался прежним (3 по умолчанию).

- `config.Settings.SubagentsParallel` + `SaveSubagentsParallel`, значение уходит в `Runner`;
- `runTask`: счётчик под мьютексом, слоты — семафором (отмена по `ctx` тоже работает);
- `execTools`: группа `task` считается параллельной только при `SubagentsParallel > 1`.

Зачем осторожно: у Local и слабых квот один слот — параллельность там только вредит.

## Замеры: индекс против grep

Новый `cmd/indexprobe` считает, сколько данных модель получает при поиске символа двумя путями.
На 20 символах этого репо: **20 вызовов / 3.3 КБ** у `find_symbol` против **40 вызовов / 392 КБ**
у `grep` + чтения файла — примерно в 120 раз меньше контекста. Отчёт:
`docs/reports/2026-11-12-index-vs-grep.md`, воспроизводится одной командой.

## MCP-first подсказка усилена

поиска нет — работает прежняя мягкая подсказка. `internal/agent/mcpfirst_test.go`.
