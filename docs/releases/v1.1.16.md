## NotCursor 1.1.16 — nc.ai

### MCP: наконец не только локальные серверы

Раньше NotCursor умел только **stdio**-MCP: локальный процесс, `npx …` / `uvx …`. Hosted-серверы
(«вставьте URL в настройки коннектора» — Suno, SaaS-коннекторы, чужие шлюзы) подключить было нельзя.

Теперь есть **Streamable HTTP** и **OAuth**:

- Settings → Агент и MCP → поле **«Добавить URL-сервер»**: вставляете `https://host/mcp`, сервер
  появляется карточкой.
- У HTTP-карточки — кнопки **«Войти»** / **«Выйти»**. «Войти» открывает браузер, вы подтверждаете
  доступ на стороне сервиса, NotCursor ловит редирект на локальный порт и сохраняет токен.
- Ответы читаются и как обычный JSON, и как SSE-поток; `Mcp-Session-Id` переиспользуется.
- Токен живёт в системном хранилище секретов (Keychain / Credential Manager), **не** в `settings.json`.
  Access-токен обновляется по `refresh_token` сам — и по истечении срока, и при ответе 401.
- Адреса проверяются: `https` обязателен, `http` разрешён только для localhost, внутренние адреса
  (RFC1918) — только с явным флагом `allowPrivate`. Редирект на чужой хост запрещён — токен не утечёт.

Ограничение: серверы, которым нужен **статический** токен, поддерживаются через заголовки в настройках
сервера. OAuth-провайдеры без динамической регистрации клиента (DCR) пока не подключаются — нужен
`client_id` от провайдера.

### Пресет «Security review» (Semgrep)

В каталоге пресетов появился **Semgrep (security review)**: `uvx semgrep-mcp`, инструменты
`security_check`, `semgrep_scan`, `semgrep_scan_with_custom_rule`. Работает локально, код никуда не
уходит. Чеклист ручной проверки и заготовка `SECURITY.md` — в `docs/security-review.md`.

### Диагностика обрыва потока

Раньше обрыв SSE выглядел как `stream read: connection reset` без подробностей. Теперь:

```
stream read: обрыв после 45 с тишины (строк получено: 12): connection reset by peer
```

Видно, молчал ли сервер до обрыва и сколько успело прийти. Работает для OpenAI-совместимых провайдеров
и для Anthropic.
