## NotCursor 0.7.8 — nc.ai

Уточнение границ проекта, которые появились в 0.7.7.

### Промежуточные результаты — под одним треугольником

Раньше после ответа в ленте оставался весь «черновик» витка: размышления, карточки инструментов,
служебные строки, промежуточные реплики агента. Теперь, когда ответ готов, всё, что было между
запросом пользователя и финальным ответом, сворачивается в один блок
**«Промежуточные результаты · N шагов»** с треугольником — клик раскрывает содержимое.

- сворачивается только **завершённый** виток: пока агент работает, шаги видны живьём;
- финальный ответ агента остаётся на виду, запрос пользователя не сворачивается никогда;
- внутрь не вкладываются лишние уровни: группы «Исследовал …» и блоки «Думал» показываются прямо
  внутри, кнопка «Развернуть всё» раскрывает и общий блок, и всё внутри;
- витков без шагов (просто вопрос → ответ) это не касается — там ничего не сворачивается.

### Список проектов — по алфавиту

Панель проектов отдавалась в порядке хранения, а новый проект вставлялся **сверху** — из-за этого
список выглядел вразнобой (алфавитным он был только пока проекты открывались по алфавиту).

Теперь `workspace.Manager.List()` сортирует выдачу по имени (регистр не важен, при равных именах — по
пути). Сортируется только выдача: порядок в `settings.json` и активный проект не меняются, поэтому
после создания, открытия или клонирования проект встаёт на своё место в алфавите, а не наверх.

### Чтение можно, изменение — только с подтверждением

В 0.7.7 системные и временные каталоги были разрешены целиком, поэтому мимо подтверждения проходили
и записи: `Set-Content C:\Windows\System32\drivers\etc\hosts`, `Remove-Item "C:\Program Files\…"`,
копирование в `ProgramData`. Теперь правило разделено по характеру команды:

| Что делает команда | Реакция |
|---|---|
| Читает в `%TEMP%`, `C:\Windows`, `Program Files*`, `ProgramData` (`Get-Content`, `Get-ChildItem`, `Test-Path`, `python -m venv %TEMP%\venv`) | молча — иначе каждая проверка требовала бы клика |
| **Меняет** что-либо вне папки проекта | подтверждение |

Под подтверждение попадают: `Set-Content`, `Add-Content`, `Clear-Content`, `Out-File`, `New-Item`,
`Remove-Item`, `Move-Item`, `Copy-Item`, `Rename-Item`, `Set-ItemProperty`, `Set-Acl`, `icacls`,
`takeown`, `attrib`, `Expand-Archive`, `Compress-Archive`, `Tee-Object`, `robocopy`, `xcopy`,
`mklink`, `chmod`, `chown`, cmd-шные `del`/`erase`/`rmdir`/`copy`/`move`/`mkdir`/`ren`,
`reg add|delete|import`, `sc create|delete|config`, `schtasks`, `netsh`, `diskpart`, `format`,
установка пакетов (`pip install`, `winget install`, `choco`/`scoop install`, `npm ci|install`),
git-мутации (`pull`, `fetch`, `checkout`, `reset`, `clean`, `merge`, `rebase`, `stash`, `apply`,
`commit`, `push`, `clone`, `rm`, `mv`, `switch`) и перенаправление вывода `>` / `>>` в файл
(`2>&1` записью не считается).

Чтение (`git status`, `git log`, `git diff`, `Get-Content`, `Select-String`, `go build`) осталось без
подтверждений — важно, чтобы защита не мешала обычной работе.

### В диалоге видно, что именно происходит

- «команда заходит в другой проект: `D:\Soft\Git\Pentest`» — чтение чужого проекта;
- «команда изменяет другой проект: `D:\Soft\Git\Pentest`» — `git pull`/`commit`/`apply` там же;
- «команда изменяет данные вне проекта: `C:\Windows\System32\drivers\etc\hosts`» — запись/удаление
  за пределами рабочей папки.

При отказе агент получает прямое указание работать в границах текущего проекта и не повторять
попытку.

### Установка (Windows 10/11, x64)

1. Скачать `nc.ai-0.7.8-windows-amd64.zip` и распаковать в любую папку.
2. Запустить `NotCursor.exe`.
3. Дальше обновления — кнопкой из приложения.
