# NotCursor 1.2.3

Убрана ложная запись, которая появлялась **после каждого** ответа:

> ↩ Прогон на бэкенде уже завершён, а сигнал о завершении не дошёл — состояние чата восстановлено, очередь пошла дальше.

## Причина

Это регрессия 1.2.2, из той же правки, что чинила «Stop неактивен». Двусторонний watchdog каждые
3 секунды сверяет экран с `ActiveRuns()`:

1. Прогон штатно завершается, приходит событие `done` → `busy` снимается.
2. Но бэкенд снимает сессию из `ActiveRuns` на мгновение позже, и ближайший тик watchdog видел
   сессию «живой» при `busy = false` — и **возвращал busy обратно** (обратная сверка).
3. Дальше срабатывала прямая сверка: две пустые проверки ≈6 с — «событие завершения потеряно»,
   закрываем дорожки и пишем ту самую запись. Внешне — после каждого ответа.

## Что исправлено

- **Окно покоя после завершения.** `finishRunUI` запоминает время последнего `done`/`error` по сессии
  (`finishedAtRef`), и обратная сверка не поднимает `busy` для сессий, где завершение было меньше
  15 секунд назад. Ложного цикла «сняли → вернули → закрыли» больше нет.
- **Запись в чат — только по делу.** «↩ Прогон…» пишется, лишь если реально закрывались дорожки
  (было что терять). Если дорожек не было — это тихо уходит в `agent.log` строкой
  `[ui] reconcile-runs: … busy снят без потери дорожек` и в чат не попадает.

## Проверки

`tsc --noEmit`, `wails build` — зелёные. Наблюдение после установки: обычный ответ завершается без
системной строки; при реальной потере события завершения запись остаётся (она и должна остаться).
