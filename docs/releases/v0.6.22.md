## NotCursor 0.6.22 — nc.ai

### Изоляция проектов (главное)

Раньше окно ввода и очередь были общими для всех проектов: вопрос, набранный в одном, мог уйти в
другой; инструменты агента работали с той папкой, которую вы открыли последней. Исправлено:

- черновик, вложения, очередь вопросов и todo-список привязаны к своему чату/проекту;
- запуск агента фиксирует свой проект на всё время работы: `read_file` / `write_file` / `grep` /
  `run_terminal` / `git_*` не уезжают в другой проект (`tools.Registry.ForRun`,
  `workspace.Manager.Scoped`, `gitx.Service.WithRoot`, отдельный `TodoStore` на запуск);
- события агента адресуются сессии (`emitFor(sid)`), транскрипт, LLM-история и usage пишутся в файл
  проекта-владельца (`chatstore.FindProject`);
- сообщение из очереди снимается только после фактического старта запуска — вопрос потерять нельзя;
- ответ фонового чата (вы уже смотрите другой проект) сохраняется сразу после завершения.

### Интерфейс

- очередь вопросов приклеена над полем ввода и видна всегда: счётчик, бейдж на вкладке чата,
  `Send now`, `×`;
- рассуждения модели скрыты под `>Thinking…` — раскрываются кликом;
- этапы работы («Этап: шаг 4/120 · прошло 1:20 · Сделано: чтение ×3, команды ×1 · Сейчас: …») и живой
  статус над вводом показываются **только по просьбе** («показывай промежуточные результаты»,
  «по этапам», «что делаешь», `interim results`, `progress updates`) либо автоматически, если агент
  молчит без вывода результата больше двух минут.

### Свои провайдеры: не один, а несколько

Раньше такой провайдер был один. Теперь можно держать несколько **своих профилей** (self-hosted):
Ollama на этом же ПК, сервер в LAN или собственный хост на VPS — важно только, чтобы он отдавал
OpenAI-совместимый API. У каждого профиля свой `baseURL` и модель; редактор в **Settings → Custom** —
добавить, дублировать, удалить (последний остаётся), выбор профиля в интерфейсе. Плюс:

- SSE-стриминг ответов своего сервера;
- восстановление tool-calls из текста для моделей, которые вызывают инструменты «словами»;
- **Custom lite** — короткий агент для слабых моделей (см. ниже);
- **Auto-models** среди тегов Ollama: берёт модели с capability `tools`, на простые задачи меньшую;
- health-pill рядом с Rules (VRAM / ping / токены-в-секунду) и подсказки по запуску.

#### Custom lite — коротко

Галочка в топбаре и ключ `localLite` в `settings.json`. **По умолчанию выключено** — свой сервер
работает как облачный агент: полный system prompt и все инструменты.

| | Lite **выкл** | Lite **вкл** |
|---|---|---|
| System prompt | полный | короткий |
| Инструменты | все (включая терминал, ssh, web, todo) | ~12: файлы, поиск, `git status/diff/log`, `ask_user` |
| Когда лучше | модель уверенно зовёт инструменты (qwen2.5-coder 7B/14B и больше) | совсем слабая модель, мало VRAM, нужно быстрее |

Включать стоит, если сервер слабый и агент задыхается на длинном промпте. Вредит на coder-моделях
7B/14B: они начинают писать «Вероятно…» вместо чтения файлов — тогда Lite **выкл** и новый чат.
Подробно, простыми словами: [`docs/local-models-ru.md`](../local-models-ru.md).

### Агент: шаги и прогресс

- лимит шагов по умолчанию 120 (было 40); в **Settings → Agent** есть «без ограничения шагов» и порог
  «предупреждать после N» — предупреждение приходит системной строкой;
- прогресс-события: milestone каждые 3 инструмента / 25 с, heartbeat каждые 30 с
  (`phase, step, total, tools, done, current`);
- в системный промпт добавлено правило: писать этапы только по просьбе или после двух минут тишины.

### Накопилось с 0.6.8

- **Терминал**: интерактивный PTY и one-shot команды, открытие по `Ctrl+Shift+T` (настройки —
  `Ctrl+Shift+S`).
- **Свои модели (self-hosted)**: несколько профилей (см. выше), SSE-стриминг, tool-calls из текста,
  Lite-режим, Auto-models, health-pill; фиксы — без `tool_choice=required`, сломанный tool-JSON не
  показывается, нет «угадай-циклов».
- Всё из разделов выше (изоляция проектов, очередь вопросов, этапы работы, лимиты шагов) — тоже новое
  относительно 0.6.8.

### Установка (Windows 10/11, x64)

1. Скачать `nc.ai-0.6.22-windows-amd64.zip` и распаковать в любую папку.
2. Запустить `NotCursor.exe` (бинарник не подписан: SmartScreen → «Подробнее» → «Выполнить в любом
   случае»).
3. Ключи провайдеров — **Settings → Providers** (хранятся в Windows Credential Manager).
