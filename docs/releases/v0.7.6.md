## NotCursor 0.7.6 — nc.ai

### ToDo можно убрать вручную (ПКМ)

Список задач агента больше не нужно выпрашивать: **правый клик по блоку ToDo** (или по отдельному
пункту) открывает меню.

| Пункт меню | Что делает |
|---|---|
| **Убрать пункт** | убирает конкретный пункт (виден текст пункта в самом меню) |
| **Убрать выполненные** | чистит закрытые пункты (completed/cancelled), незакрытые остаются |
| **Скрыть блок в чате** | блок исчезает из ленты, но план у агента остаётся — вернётся, когда появится новый набор пунктов |
| **Убрать ToDo целиком** | чистит список в приложении и скрывает блок: если часть плана делается на другой машине, её не надо просить «убери пункты 4–10» |

Убранные вручную пункты запоминаются: следующий `todo_write` с merge их не воскрешает — они
возвращаются только вместе с новым планом (`merge=false`). Так сценарий «пункты 4–10 делаем на другой
машине, оставь только локальные» решается двумя кликами, без просьб к агенту.

### Долгие шаги предупреждают о себе заранее

Раньше долгая работа (сборка, скачивание весов, индексация, прогон тестов по большому репозиторию)
могла идти часами без объяснений: в чате мелькали шаги, и было непонятно, сколько ещё ждать.

- В системный промпт агента добавлено правило: **перед** таким шагом одной строкой сказать, что
  делается и сколько это примерно займёт («сборка векторов ~20–40 минут, буду проверять прогресс»),
  а долгие команды запускать в фоне (`is_background=true`) и опрашивать через `command_status`,
  а не «ждать» в foreground через `Start-Sleep`. Пока шаг идёт — давать промежуточную строку раз в
  пару минут: что сделано, что ещё работает, что дальше.
- Дополнительно приложение само помечает долгий шаг в чате: если `run_terminal` запускается с
  `timeout_sec ≥ 120` или в фоне, до старта выводится строка вида
  «Долгий шаг: сборка векторов — в фоне, лимит до 30 мин. Промежуточные результаты покажу по ходу».
  Это страховка на случай, если модель про сроки промолчала.

### Кнопка Project → Clone repository…

В меню **Project ▾** появился третий пункт: **Clone repository…** — клонирует репозиторий в выбранную
папку и сразу открывает его как проект, так что новый проект можно начать не только с существующей
папки или пустой директории.

- **Способ доступа выбирается сам.** Если SSH настроен и хост отвечает — клонируем по SSH; иначе по
  HTTPS. Проверка идёт через `git ls-remote` тем же ssh, который потом применит `clone` (`core.sshCommand`,
  ключи, `~/.ssh/config`), поэтому «настроен» означает «реально есть доступ к этому репозиторию»,
  а не «в ~/.ssh есть файл ключа».
- Порт и пользователь для SSH-варианта берутся из ссылки, а если их там нет — из `~/.ssh/config`
  (`Host git.papatramp.ru` → `Port 2222`, `User git`).
- **Понимаем ссылки:** `ssh://git@host:port/path`, `git@host:path`, `https://host/path`,
  `http://…`, локальные пути и `file://`.
- Папка создаётся как `<выбранная>/<имя репозитория>`; её путь виден в диалоге до нажатия
  «Клонировать». Если папка уже существует и не пуста — понятная ошибка вместо тихой перезаписи.
- **Если доступа нет ни по SSH, ни по HTTPS**, в диалоге видно обе попытки с их ошибками и подсказку,
  что проверить: ключ в аккаунте (`Settings → SSH keys`), права на репозиторий, сохранённый токен для
  HTTPS. Клонирование ждёт до 5 минут, при обрыве промежуточный каталог убирается.

### Кнопка «Проверить обновления» действительно снимает баннер

После установки 0.7.5 в шапке висел баннер «Версия 0.7.5 та же, но на GitHub другая сборка», и кнопка
**Проверить обновления** в настройках его не убирала. Причина не в GitHub и не в логике проверки:
свежая проверка предложения не давала, но интерфейс при этом **не сбрасывал прошлое состояние** —
старый баннер оставался на экране, и кнопка выглядела сломанной.

- Ручная проверка теперь обнуляет предложение, если свежий ответ — «обновлений нет»: баннер
  исчезает сразу, а в настройках появляется строка «Обновлений нет — установлена последняя версия
  0.7.6 (ваша сборка 12-символьный хеш)».
- То же и на стороне приложения: после ручной проверки без предложения кеш «доступен апдейт»
  очищается, чтобы кнопка «Скачать» из старого баннера не переустанавливала ту же версию.
- В самом баннере «та же версия, другая сборка» теперь видно оба хеша: `ваш файл <хеш>, на GitHub
  <хеш>` — сразу понятно, разошлись ли сборки (при копии релиза из `build/bin` они совпадают).

### Причина того баннера (на заметку)

В релиз 0.7.5 был положен `.sha256` с хешем **архива**, а апдейтер сравнивает хеш **бинарника внутри
архива** (`LocalExeHash`). Пока хеши не совпадают, приложение считает сборку «другой». Sidecar
перезалит правильно, а чтобы ошибка не повторялась, в репозитории появился
`scripts/macos-zip-sidecar.sh`: `./scripts/macos-zip-sidecar.sh <zip>...` пишет sidecar из содержимого
архива, `--check <zip> <exe>` сверяет его с локальным файлом.

### Установка (Windows 10/11, x64)

1. Скачать `nc.ai-0.7.6-windows-amd64.zip`, распаковать, запустить `NotCursor.exe`.
2. Ключи провайдеров — **Settings → Providers** (Windows Credential Manager).

### Установка (macOS 12+, Apple Silicon и Intel)

1. Скачать `nc.ai-0.7.6-macos-arm64.zip` или `nc.ai-0.7.6-macos-universal.zip`, распаковать.
2. Перенести `NotCursor.app` в «Программы», запустить (ad-hoc подпись: правый клик → «Открыть»).
