## NotCursor 1.1.17 — nc.ai

### Лимиты провайдеров: ожидание по заголовкам и резервный провайдер

Разбор `429` был честным только у Anthropic и Local — остальные провайдеры отдавали одну строку
«Превышен лимит запросов…», и агент повторял вслепую, не зная срока сброса. Теперь одинаково у всех:

- любой `429` (и Z.ai `1302`) — это `*llm.RateLimitError` из общего `llm.NewRateLimitError`;
- разбираются `Retry-After` (секунды и HTTP-дата), `x-ratelimit-reset-*` (длительность **или**
  unix-время сброса), `anthropic-ratelimit-*-reset` (RFC3339) — раньше у Anthropic ожидание было нулевым;
- в тексте ошибки — остаток квоты и `limit_source` («лимит по токенам» / «по запросам» / «по кредитам»,
  как отдаёт OpenRouter);
- короткий лимит агент пережидает и повторяет сам, суточный — сразу отдаёт ошибку с подсказкой сброса.

**Резервный провайдер.** Если основной упёрся в длинный лимит или перегружен (503/529), прогон больше
не падает: он **один раз** переходит на резерв и продолжает работу.

```json
{
  "activeProvider": "openrouter",
  "openrouterModel": "deepseek/deepseek-v4-flash:free",
  "fallbackProvider": "deepseek",
  "fallbackModel": "deepseek-v4-flash"
}
```

В чате появляется строка «Основной провайдер не может ответить (исчерпан лимит requests) — продолжаю на
резервном (deepseek)», дальше работа идёт как обычно: инструменты, история, стоимость — всё на резерве.

Правила, чтобы не сделать хуже:

- переключение **одно** за прогон — второй фолбэк не делаем (защита от цикла);
- короткий лимит (меньше минуты) выгоднее переждать — провайдер не меняется;
- Local не подставляется в резерв, если в запросе есть изображения;
- тот же самый провайдер в резерв не ставится — фолбэк просто выключен.

Настройка — в `settings.json` (поля `fallbackProvider` / `fallbackModel`); в UI поле появится
следующим шагом, до тех пор можно править файл или вызвать `SaveFallbackProvider` / `SaveFallbackModel`.
