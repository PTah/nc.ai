## NotCursor 1.1.13 — nc.ai

### Что изменилось

Многофолдерная «рабочая область» была привязана к папке-**якорю**: в ней жили чаты, замок и память,
дополнительные корни можно было только добавлять. В 1.1.13 workspace — **отдельная сущность**, как
`.code-workspace` в Cursor: имя + список папок, без главной.

- **`Menu ▾ → Project → New workspace…`** — диалог с названием и папками: «Добавить папку…» (сколько
  нужно), `↑` / `✕` меняют порядок и убирают папку, брошенные в окно каталоги попадают прямо в
  открытый диалог. Название можно не вводить — подставится «api + web + docs».
- **Хранение в настройках**: `Settings.Workspaces` (ключ, имя, папки). Ключ — служебная папка в
  `AppData/NotCursor/workspaces/ws-<id>`: она нужна только как стабильный идентификатор чатов и замка,
  кода в ней нет. Папки с кодом **не копируются и не меняются**.
- **Редактирование и удаление**: `Edit workspace folders…` / ПКМ по workspace, `Workspace from this
  project…` собирает workspace из открытого проекта (сам проект и его чаты остаются). Закрытие
  workspace удаляет определение и служебную папку — реальные папки на диске не трогаются.
- **Недоступная папка не роняет пространство**: при восстановлении после запуска (отключённый диск,
  внешний SSD) в работу берутся только те папки, что на месте; остальные остаются в настройках.

### Что с этим делает агент

| Что | Как в нескольких папках |
|---|---|
| Файлы, `grep`, `glob`, `find_files` | пути начинаются с имени папки: `api/main.go`; поиск идёт по всем папкам, `path=api` сужает |
| `find_symbol`, `project_search`, карта проекта | индекс строится по каждой папке отдельно, результаты склеиваются по кругу (одна шумная папка не вытесняет остальные) |
| `run_terminal` | **`cwd` обязателен** — имя папки (`api` или `api/cmd`); все папки workspace считаются «внутри проекта» |
| `git_status`, `git_diff` | без `repo` — по всем папкам, с заголовком `## имя`; `repo=web` — одна |
| `git_log`, `git_commit`, `git_push` | репозиторий выводится из префикса путей или задаётся `repo`; один коммит — один репозиторий |
| `read_lints` | `go vet` в каждой папке с `go.mod`; для файла — в его папке |
| Память (`remember` / `recall`) | одна на workspace; пути заметок разворачиваются по папкам (и корректно помечаются stale) |
| Правила Cursor | `.cursor/rules`, `.cursorrules`, `AGENTS.md` **всех** папок, плюс глобальные |

В системный промпт добавлен блок `<workspace_folders>` — карта «имя папки = путь» и правила
адресации путей; карта символов делится по бюджету на каждую папку. Для проекта из одной папки
поведение не меняется: блока нет, пути остаются как есть.
