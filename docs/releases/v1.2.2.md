# NotCursor 1.2.2

Исправлено рассогласование UI и бэкенда по признаку «идёт прогон».

## Симптом

Прогон шёл (агент выполнял шаги, текст продолжал идти в окно ответа), но кнопка **Stop** была
неактивна — фронт считал чат свободным. При этом закрыть приложение было нельзя: бэкенд честно
держал `activeRuns` и показывал «идёт прогон». Получалась ловушка: остановить нельзя, выйти нельзя.

## Причина

Состояние «занято» в UI выводится из `runCountBySession` (счётчик дорожек прогона), а «идёт прогон»
на бэкенде — из `activeRuns`. Watchdog сверял их только **в одну сторону**: если дорожка «зависла
занятой», он её закрывал, но если дорожка **пропала** (перезагрузка WebView посреди прогона, потеря
события старта), то обратно busy не поднимал — счётчик оставался 0, а прогон в Go продолжался.

## Что исправлено

- **Двусторонний watchdog**: раз в 3 с сверяемся с `ActiveRuns()` в обе стороны.
  Если бэкенд говорит «идёт прогон», а фронт уже сбросил busy — busy возвращается, Stop снова
  активен, очередь и выход работают. Старое поведение (закрытие потерянных дорожек по двум пустым
  сверкам) сохранено.
- **Самовосстановление дорожки из потока**: `setRunLaneItems` теперь, получив событие для `runId`,
  о котором фронт ещё не знает (после перезагрузки WebView), сам заводит дорожку и поднимает
  счётчик. Это чинит не только Stop, но и отрисовку хвоста ответа, пришедшего уже после перезагрузки.
  Защита от дубликатов — `registeredRunsRef`.

## Проверки

`tsc --noEmit`, `go build ./...`, `wails build` — зелёные.
