## NotCursor 0.8.5.4 — nc.ai

### MCP-пресеты заработали там, где Homebrew (и на любом PATH из Finder)

Симптом: нажимаешь **Codebase Memory** в `Settings → MCP`, а он либо остаётся со стрелкой
«установить», либо падает «npm не найден» — при том, что Node и пакет установлены. Причина: macOS
запускает приложение из Finder с PATH `…/usr/bin:/bin:/usr/sbin:/sbin`, а Node/npm из Homebrew лежат
в `/opt/homebrew/bin`; эти каталоги приложение не просматривало. Похожая история ждала `uvx`, `python3`
из brew и npm-обёртки (`node` для сервера тоже берётся из PATH).

Что исправлено:

- **Поиск бинарей** (`internal/mcp/install.go`): добавлены каталоги пакетных менеджеров —
  `/opt/homebrew/bin`, `/opt/homebrew/sbin`, `/usr/local/sbin`, `~/.cargo/bin`, `~/.bun/bin`,
  `~/.local/bin`, `~/.npm-global/bin` (+ `/snap/bin` на Linux, прежние пути на Windows).
- `lookPath` для `npm`/`npx`/`uvx`/`python` теперь ищет по тем же каталогам, а не только по PATH
  приложения — ветка «уже установлено» наконец срабатывает, и лишний `npm install -g` не запускается.
- **PATH для MCP-серверов**: дочернему процессу сервера теперь выдаётся PATH с этими каталогами,
  поэтому Node/Python-обёртки (`#!/usr/bin/env node`) запускаются, даже если приложение открыто из
  Finder.
- В пресете **Codebase Memory** исправлено имя инструмента: `trace_call_path` (такого инструмента в
  сервере нет) → `trace_path`; в подсказке уточнено, что `search_graph.name_pattern` — это **regex**,
  а не glob (проверено на индексе: `name_pattern: "Stdio"` находит `StartStdio`, `query` работает по
  BM25).

### Установка (Windows 10/11, x64)

1. Скачать `nc.ai-0.8.5.4-windows-amd64.zip`, распаковать, запустить `NotCursor.exe`.
2. Ключи провайдеров — **Settings → Providers** (Windows Credential Manager).

### Установка (macOS 12+, Apple Silicon и Intel)

1. Скачать `nc.ai-0.8.5.4-macos-arm64.zip` или `nc.ai-0.8.5.4-macos-universal.zip`, распаковать.
2. Перенести `NotCursor.app` в «Программы», запустить (ad-hoc подпись: правый клик → «Открыть»).
