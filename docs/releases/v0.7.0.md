## NotCursor 0.7.0 — nc.ai

### Больше не мелькают окна cmd/PowerShell

Служебные процессы, которые приложение запускает для проверки окружения (`get_env_info`:
`go version`, `node -v`, `npm -v`, `python --version`) и для линтов (`go vet`), стартовали
**без** флага «не показывать окно». Windows для каждого такого процесса открывал консольное
окно: при новом чате, когда агент сверял тулчейн, по экрану проносились 2–3 окна с `npm`/`node`
в заголовке. Теперь они запускаются скрыто (`CREATE_NO_WINDOW` + `HideWindow`) — как уже делали
`git` и shell-команды. Вывод по-прежнему читается через пайпы, на результат `get_env_info` и
`read_lints` это не влияет.

### Размышления модели больше не попадают в ответ

Часть OpenAI-совместимых эндпоинтов отдаёт thinking не отдельным полем, а инлайном в текст:
`<think>…</think>ответ`. Раньше такой блок оставался в ответе, портил проверку языка и уезжал
в историю чата. Теперь ведущие блоки (`<think>`, `<thinking>`, `<reasoning>`) отделяются и
уходят в коллапс «Думал»:

- в потоке — разделитель работает по дельтам, даже если тег разрезан между чанками;
- в собранном ответе — thinking вычищается из `content` перед сохранением в историю;
- литеральный `<think>` в середине ответа (пример кода) не трогается.

### Лимиты провайдеров: ждём и повторяем сами

У бесплатных тарифов и у агрегаторов лимиты жёсткие (например 5 запросов в минуту и 200 в
сутки), а агент делает десятки шагов. Теперь на `429` приложение читает `Retry-After` и
`x-ratelimit-reset-*`, показывает остаток из `x-ratelimit-remaining-*` и в чат уходит понятная
строка:

```
Local API: лимит запросов (429), повтор через 42 сек: Requests rate limit exceeded (запросы: 5, осталось 0).
```

Если провайдер просит подождать не дольше минуты — агент ждёт и повторяет запрос сам
(в чате видно «Провайдер ограничил частоту запросов (429). Жду 42 сек и повторяю (1/3)…»).
Суточный лимит не ждём: ошибка показывается сразу, без бесполезного ожидания.

### План задач уезжает в поток

ToDo-панель закреплялась внизу ленты до конца прогона, поэтому список `7/7` продолжал висеть
под ответом, пока агент ещё писал. Теперь, как только все пункты закрыты или отменены, панель
встаёт в поток на место закрытия (свёрнутая), а внизу остаётся только текущая активность.

### Что проверить

1. Новый чат → вопрос, из-за которого агент вызывает `get_env_info`: окна консоли не появляются.
2. Запрос к модели, которая думает тегами: теги не видны в ответе, текст thinking — в «Думал».
3. Упереться в лимит (5 RPM): в чате — «Жду … сек и повторяю», затем ответ без ручного перезапуска.
4. Выполнить план до конца: панель ToDo сворачивается и уезжает вверх вместе с текстом.
