## NotCursor 1.2.6 — nc.ai

### Новый проект одной фразой

«Создай репо `my-service` и выложи его на домашний Gitea» — и всё готово: папка, git-репозиторий,
первый коммит, пустой репозиторий на хостинге, `origin` + `push`, проект в дашборде, и прогон уже
работает там.

Новый инструмент — **`create_project`**:

| Шаг | Что делает |
|---|---|
| 1 | Создаёт папку (рядом с текущими проектами или в `dir`) и **проект в дашборде** с этим именем |
| 2 | `git init -b master` + `README.md` + `.gitignore` + первый коммит `chore: initial commit` |
| 3 | Создаёт **пустой** репозиторий по API: `github`, `gitea`, `gitea` (`auto_init: false` — первый коммит наш) |
| 4 | Добавляет `origin` (SSH-адрес от API, если есть) и пушит `master` с `-u` |
| 5 | Возвращает маркер `switch_project`: прогон завершается handoff-сводкой, приложение открывает новый проект и запускает прогон там |

Параметры инструмента: `name` (обязательно), `dir`, `remote` (`github` / `gitea` /
`none`), `owner` (организация; пусто — личный аккаунт токена), `description`, `private` (по умолчанию true).

**Настройка (один раз).** Settings → Агент и MCP → блок **«Git-хостинги»**:

- адрес Gitea-сервера, например `https://git.example.com` (для GitHub адрес не нужен);
- токены: Gitea — Settings → Applications → Generate token; GitHub — personal access token с правом `repo`.
  Ввод по Enter; в поле отображается только «токен задан». Токены сохраняются в системном хранилище
  секретов (Keychain / Credential Manager), в `settings.json` их нет.

**Ошибки не отменяют работу.** Если токена нет, хостинг недоступен или имя занято, локальная часть
всё равно создаётся (папка, репозиторий, первый коммит, проект в дашборде), а в ответе будет
человеческая причина: «нет токена», «репозиторий уже существует (409)», «push не прошёл: …».

### Прочее

- `internal/gitrepo` — клиент API Gitea/GitHub (создание пустого репозитория, внятные ошибки 401/403/409);
  тесты на пути `/user/repos`, `/orgs/{owner}/repos`, заголовок `Authorization`, отказы.
- `internal/gitx`: `InitRepo`, `AddRemote`, `PushIn` — git-операции в каталоге, который ещё не открыт
  в рабочем пространстве.
- README — раздел «Новый проект одной фразой».
