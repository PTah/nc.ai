## NotCursor 1.1.10 — nc.ai

### Что проверяли

Ревью нового клонирования в 1.1.9 (`internal/gitx/clone_api.go` — zipball через GitHub REST,
`CancelClone`, `unzipFlat`) плюс полный прогон сборки и тестов на macOS.

### Что нашли и починили

**1. У скачивания и распаковки не было лимитов.** `io.Copy(dest, resp.Body)` качал сколько угодно, а
`unzipFlat` разворачивал архив без счёта. Один битый или подменённый ответ (сжатый архив на 1 МБ
разворачивается в гигабайты) забивал диск в staging, а `CancelClone` пришлось бы жать вручную.
Теперь:

| Лимит | Значение | Где |
|---|---|---|
| скачивание | 512 МБ (`Content-Length` + `io.LimitReader`, ответ без длины тоже покрыт) | `downloadGitHubZipball` |
| распаковка | 3 ГБ суммарно и на файл по факту скопированных байт (размер в заголовке zip может врать) | `writeZipFile` |
| число записей | 100 000 | `unzipFlat` |

Сообщения человеческие: «архив слишком большой: N МБ (лимит 512 МБ) — клонируйте через git».

**2. `os.RemoveAll(target)` мог удалить файл.** Проверка «папка не пуста» срабатывала только на
каталог: если на месте проекта лежал **файл** с тем же именем, `os.ReadDir` возвращал ошибку, поток шёл
дальше и `cloneGitHubAPI` молча сносил этот файл перед распаковкой. Теперь `Clone` сначала смотрит
`os.Stat` и отказывает: «это файл, а не папка; выберите другую папку».

**3. Общий HTTP-клиент для zipball.** Было `&http.Client{Timeout: 0}` с дефолтным транспортом и без
таймаута заголовков: зависший GitHub держал диалог до ручной отмены. Стало — свой транспорт (пул
соединений переиспользуется, как в 1.1.5), `ResponseHeaderTimeout: 30s`, те же 10 редиректов.

### Кросс-платформенные тесты (были красными до этого релиза)

На macOS стабильно падали три пакета — из-за путей Windows в ожиданиях. Это маскировало новые
регрессии, поэтому привёл к общему знаменателю:

- `gitx.parseRemote`: путь `D:\repos\origin` не распознавался как локальный (`filepath.IsAbs` знает
  только текущую ОС и падал в «не понимаю ссылку»). Добавлен `isWindowsAbsPath` — теперь строка из
  Windows работает и на маке.
- `chatstore.projectDisplayName`: имя проекта бралось через `filepath.Base`, поэтому для
  `D:\Soft\Git\nc.ai` из архива возвращалось целиком. Теперь режем по обоим разделителям, `filepath.Base`
  остаётся запасным вариантом.
- `tools` `TestCheckCommandScope`: кейсы с `C:\Windows`, `..\..` и `$env:USERPROFILE` проверяют
  семантику PowerShell — на macOS та же строка это просто имя файла. Эти девять кейсов помечены как
  Windows-only и пропускаются на других ОС (логика охранника не ослаблена: на Windows они по-прежнему
  выполняются).

Итог: `go test ./...` на macOS — **всё зелёное**, без известных падений.
