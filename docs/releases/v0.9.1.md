## NotCursor 0.9.1 — nc.ai

### Зачем

17 октября 2026 DeepSeek открыл собственные Search и Fetch API (`POST /v1/tools/search`,
`POST /v1/tools/fetch`). До этого NotCursor искал веб скрейпом DuckDuckGo, а страницы качал своим
HTTP-клиентом и вырезал текст регэкспами. Серверный поиск DeepSeek — это ранжирование, операторы и
готовый Markdown, за $0.75 на 1000 успешных запросов.

Раньше в `docs/exchange-protocols/deepseek.md` стояло решение «не используем»: у нас не было
потребности, а платить за каждый поиск без спроса — плохая идея. Теперь это **опция**, которая
включается только явным выбором.

### Что появилось

- `internal/netx/deepsearch.go` — клиент Search & Fetch: bearer-ключ DeepSeek, `count` 1–50,
  `need_content`, `ori_question`, разбор `results[]` (title, url, snippet, summary, content,
  site_name, date, rerank_score, authority), обрезка summary до 800 байт и страницы до 120 КБ,
  снятие markdown-экранирования (`\#`, `\:`), которым сервер отдаёт страницу, и ошибки в виде
  `DeepAPIError{Status, Code}` из OpenAI-совместимого конверта.
- `internal/tools/web.go` — выбор провайдера для `web_search` и `fetch_url`:
  `duckduckgo` (по умолчанию) / `auto` (DeepSeek при наличии ключа DeepSeek) / `deepseek`.
  Любая ошибка API (402 нет баланса, 403 сайт закрыт, 404 пустая страница, 408/429/5xx, обрыв)
  откатывается на прежний путь, а в ответе появляется пометка — молчаливых подмен нет.
- `fetch_url` в режиме DeepSeek получает страницу уже в Markdown, поэтому больше не нужен
  HTML→текст на нашей стороне; при отказе — старый прямой GET.
- SSRF-проверка (`netx.CheckURL`) выполняется **до** отправки URL в DeepSeek: серверный fetch не
  становится обходом блокировки LAN/loopback.
- Настройка `webToolsProvider` в `settings.json` и переключатель Settings → Agent →
  «Веб-поиск и страницы» с пояснением про тариф и откат.
- Ключ берётся из того же хранилища секретов, что и чат (`config.APIKey(ProviderDeepSeek)`), — второй
  раз вводить не нужно; в `settings.json` он, как и раньше, не пишется.

### Почему по умолчанию DuckDuckGo

Тариф per-request: 1000 поисков = $0.75, но и 100 тысяч = $75. Внутреннее правило проекта
(`docs/exchange-protocols/deepseek.md` §14) запрещает включать серверный поиск неявно, поэтому
умолчание — бесплатный путь, а DeepSeek — осознанный переключатель. Режим `auto` существует для тех,
кто не хочет думать: он смотрит только на наличие ключа DeepSeek.

### Проверка

- `go test ./internal/netx/... ./internal/tools/... ./internal/config/...` — зелёные: разбор успешного
  ответа, пустая выдача, 402 с текстом ошибки, Markdown-страница, пустой `content`, блокировка
  приватного адреса и `file://`, отказ при пустом запросе/URL, нормализация настройки и её сохранение.
- `go build ./...`, `go vet ./...`, `npm --prefix frontend run build` — без ошибок.
- Живой прогон на реальном ключе: `web_search` в режиме DeepSeek отдаёт `hits · deepseek` с полями
  `score`/`authoritative`; при отключённом ключе `deepseek`-режим объясняет, что переключить, вместо
  падения шага.

### Установка (Windows 10/11, x64)

1. Скачать `nc.ai-0.9.1-windows-amd64.zip`, распаковать, запустить `NotCursor.exe`.
2. Settings → Agent → «Веб-поиск и страницы»: `DuckDuckGo` (по умолчанию), `Авто` или `DeepSeek`.
3. Ключ DeepSeek нужен только для двух последних режимов — Settings → Providers.

### Установка (macOS 12+, Apple Silicon и Intel)

1. Скачать `nc.ai-0.9.1-macos-*.zip`, распаковать.
2. Перенести `NotCursor.app` в «Программы», запустить (ad-hoc подпись: правый клик → «Открыть»).
