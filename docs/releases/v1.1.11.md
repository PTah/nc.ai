## NotCursor 1.1.11 — nc.ai

### Зачем

«Запускаю клонирование `https://github.com/zhu1090093659/dsh-trading` — и непонятно, идёт оно или
нет: ни прогресс-бара, ни признаков жизни». Так и было: в диалоге клонирования единственной реакцией
на нажатие была кнопка «Клонирую…» и подпись «Отменить» — без этапа, без процентов, без байтов. На
репозитории в 14 МБ это ещё терпимо, на крупном — выглядит как зависание.

Заодно проверил сам тот репозиторий: zipball через GitHub API — **14 МБ, 2972 файла, 43 МБ после
распаковки**, скачивается за секунды. То есть клон не висел, ему просто нечем было отчитаться.

### Что изменилось

- **Прогресс по этапам** (`internal/gitx`: `Progress{Phase, Percent, Detail}` + `Service.OnProgress`):
  - `download` — «Скачиваю архив GitHub: 4.2 МБ из 14 МБ» (считаем записанные байты, `Content-Length`
    даёт процент; ответ без длины показываем байтами);
  - `unpack` — «Распаковываю: 1200 из 2972 файлов»;
  - `git` — `git clone` теперь запускается с `--progress`, stderr читается сканером по `\r` и `\n`:
    «получение объектов: 45%», «разрешение дельт: 10%», «подсчёт объектов: 7%»;
  - `open` — «Открываю проект…».
- **Событие `clone:progress`** из `app.go` → фронтенд слушает его, пока диалог открыт.
- **В диалоге** появились полоса прогресса и строка этапа. Когда процент неизвестен (git ещё считает
  объекты), полоса «бежит» — движение видно, но 0 % не показываем как факт.
- Троттлинг: события не чаще 8 раз в секунду, чтобы render не молотил на каждом чанке.
- `Отменить` работает на любом этапе — скачивание обрывается контекстом, `git clone` убивается
  процессом (это было и раньше, теперь видно, что обрывать).

### Проверка

- `internal/gitx/clone_progress_test.go`: разбор строк `git clone --progress` (включая `remote:` и
  `\r`-перерисовку), сплиттер `\r`/`\n`, форматирование байтов, `progressWriter` (счёт и троттлинг).
- `go vet ./...`, `go test ./...` — зелёные целиком; `npx tsc --noEmit`, `vite build` — чисто;
  `gofmt -l` по изменённым файлам пусто.
- `./build.sh` — macOS 1.1.11, версия в бандле совпадает с тегом.
