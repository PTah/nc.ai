# ToDo: phase 5 — warm project-tree / inline-режим

Статус: **отложено** (после пунктов 1–4 кэш-оптимизации).

## Что это

Опциональные улучшения поверх уже сделанного стабильного system-префикса и sticky-модели:

1. **Warm project-tree** — один стабильный early-блок (дерево файлов проекта) сразу после system prompt, чтобы удлинить кэшируемый префикс, когда агент ещё не читал файлы tools’ами.
2. **Inline-режим (Ctrl+K / правки в файле)** — отдельный контекст и история от бокового чата, чтобы не смешивать длинный chat-history с точечными правками кода.

## Для чего

| Идея | Зачем |
|------|--------|
| Warm tree | Больше `prompt_cache_hit_tokens` на первых шагах run, пока tools ещё не наполнили историю; имеет смысл только если метрики hit% покажут короткий префикс. |
| Inline отдельно | Не сбрасывать кэш чата правками «в файле» и наоборот; две разные «сессии» префикса у провайдера. |

## Когда браться

- После того как в UI стабильно видно hit/miss %.
- Если hit% в обычном agent-чате всё ещё низкий при длинных сессиях.
- Когда появится продуктная нужда в Ctrl+K / inline-edit.

## Чего не делать сразу

- Не заливать open-tabs / current-file в каждый chat-запрос вместо tools — это другая архитектура и часто дороже на cache miss.
