# MCP в NotCursor — дизайн (без кода)

Статус: **черновик дизайна**, реализации нет. Документ описывает, как подключить
MCP-серверы (Model Context Protocol) к нашему агенту, что для этого уже есть в проекте,
какие транспорты поддержать в первую очередь и где грабли.

Зачем: одна шина инструментов вместо десятка прошитых интеграций. Пользователь на Custom-
провайдере (Ollama / LM Studio / любой OpenAI-совместимый эндпоинт) получает доступ к чужим
системам — карты, браузер, базы, трекеры — без нашей работы над каждой из них.

Не-цели первой версии: не заменять наши встроенные инструменты, не превращать Settings в
каталог mcp-маркетплейса, не поддерживать OAuth и `sampling` в MVP.

---

## 1. Как устроен MCP (минимум, который нужно знать)

- Транспорт: **JSON-RPC 2.0**, по одному сообщению на строку.
- Три транспорта в природе: **stdio** (клиент запускает процесс сервера), **Streamable HTTP**
  (основной для удалённых), **SSE** (устаревающий, но жив у многих серверов).
- Версии протокола на сегодня: `2024-11-05`, `2025-03-26`, `2025-06-18`. Клиент объявляет свою
  версию в `initialize`, сервер отвечает своей — нужно согласовывать и уметь откатываться.
- Жизненный цикл: `initialize` → нотификация `initialized` → рабочие методы:

| Метод | Что даёт | Нужно в MVP |
|---|---|---|
| `tools/list` | имя, описание, **JSON Schema** входных параметров | да |
| `tools/call` | результат по инструменту | да |
| `notifications/*` (`progress`, `tools/list_changed`) | прогресс, изменения | да, минимум `progress` |
| `resources/list`, `resources/read` | файлы/данные сервера как ресурсы | нет |
| `prompts/list`, `prompts/get` | готовые промпты | нет |
| `sampling/createMessage` | сервер просит у **клиента** генерацию | нет (см. §9) |
| `roots/list` | клиент сообщает серверу корни рабочей области | вторая версия |

- Инструмент в MCP несёт необязательные аннотации: `readOnlyHint`, `destructiveHint`,
  `idempotentHint`, `openWorldHint`. Это готовая подсказка для наших подтверждений.

**Ключевое для нас:** `tools/list` возвращает ровно `name` + `description` + `parameters`
(JSON Schema). Наш `llm.ToolSpecFunction` (`internal/llm/types.go:44-48`) — это те же поля.
Конвертации нет, есть только переименование с префиксом.

## 2. Модель конфигурации

Храним в `internal/config` (Settings), секреты — в `internal/secrets` (Keychain на macOS,
Credential Manager на Windows). В `settings.json` секретов быть не должно.

```jsonc
// Settings.MCPServers — черновик формы
{
  "mcpServers": [
    {
      "id": "google-maps",            // префикс инструментов: mcp:google-maps:*
      "label": "Google Maps",
      "enabled": true,                // вкл/выкл сервер
      "transport": "stdio",           // stdio | http
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-google-maps"],
      "cwd": "",                      // рабочая папка, пусто = папка проекта
      "env": { "GOOGLE_MAPS_API_KEY": "ключ из keychain" },
      "envPassthrough": [],           // явный allowlist чужих переменных окружения
      "autoStart": "lazy",            // lazy (по первому вызову) | on-app-start
      "timeoutSec": 60,               // на tools/call
      "toolFilter": {                 // какие инструменты вообще показывать модели
        "mode": "allowlist",          // allowlist | all
        "tools": ["maps_geocode", "maps_search_places"]
      },
      "scopes": ["chat"]              // chat | project | global
    },
    {
      "id": "cognee",
      "label": "Cognee memory",
      "transport": "http",
      "url": "http://127.0.0.1:8000/mcp",
      "headers": { "Authorization": "Bearer <из keychain>" },
      "enabled": false
    }
  ]
}
```

Правила формы:

1. `id` уникален и неизменяем после создания — он попадает в имя инструмента.
2. Токены и ключи — только через `secrets`: в UI поле ввода с маской, в JSON-экспорт не попадают.
3. Если ключ не задан, сервер можно сохранить, но он будет «не настроен» и не запустится.
4. Импорт/экспорт — в формате, привычном по Claude Desktop / Cursor / VS Code
   (`{"mcpServers": {...}}`), чтобы человек мог скопировать блок из README сервера.
   При импорте: ключи вида `${input:...}` (VS Code) и `***` не подставляем — просим ввести в UI.

## 3. Как инструменты попадают в агентский цикл

1. После `tools/list` превращаем каждый инструмент в наш `ToolSpec`:
   - `name`: `mcp:<serverId>:<toolName>` — плоско, без вложенности, чтобы не ломать провайдеров
     с ограничением на длину/символы в имени; в UI показываем человекочитаемо.
   - `description`: описание сервера + пометка `[MCP · <label>]`, чтобы модель и человек видели
     источник.
   - `parameters`: JSON Schema как есть.
2. Вызов: `tools/call` с исходным локальным именем, аргументы — как их собрала модель.
3. Результат: `content[]` бывает `text`, `image`, `resource`. Наш ответ — текст; изображение
   показываем как вложение в чате (как скриншот), `resource` — как файл-вложение.
4. `isError: true` → помечаем результат как ошибку инструмента (не как «ответ модели»).
5. `notifications/progress` → строка прогресса (`internal/agent/progress.go`), то есть в живой
   строке будет «Ищу рестораны рядом · MCP google-maps: maps_search_places».
6. Длинные ответы режем теми же правилами, что и локальные инструменты
   (`internal/agent/compact.go`): у Custom-провайдеров контекст маленький.

## 4. Контекстный бюджет (то, что чаще всего ломает идею «подключить всё»)

Схемы инструментов в промпте стоят токенов: Playwright MCP отдаёт два-три десятка инструментов
с подробными схемами — это тысячи токенов в **каждом** запросе, и локальная модель на 8–32k
тонет ещё до начала работы. Поэтому:

- По умолчанию сервер добавлен, но **выключен**, и в промпт попадают только инструменты из
  `toolFilter` (по умолчанию — ничего, пользователь отмечает галочками осознанно).
- Показываем в карточке оценку: «инструментов N, схемы ≈ X токенов».
- Инструменты включаются в область видимости: чат / проект / глобально. В MVP — только «этот чат».
- Если у сервера больше ~15 включённых инструментов — предупреждение в UI.
- Один инструмент из двух серверов с одинаковым именем не конфликтует из-за префикса, но в UI
  показываем дубли отдельным предупреждением.

## 5. Транспорты: что делать в MVP и что потом

### stdio (MVP)

- Запускаем `command args` с фильтрованным окружением, читаем stdout построчно, пишем в stdin.
- stderr сервера — в наш лог панели «Логи сервера» (иначе «почему не работает» не отладить).
- Требования: Node/npx или python/uv должны быть установлены **у пользователя**. Если команды
  нет — карточка «не настроен: npx не найден», а не тихий отказ.
- Таймауты: `initialize` 10 с, `tools/list` 10 с, `tools/call` 60 с (настраивается), хард-килл
  по истечении.
- Перезапуск: не более N раз с backoff; после N — статус «ошибка» и текст последней строки stderr.
- Остановка: по выходу приложения завершаем процессы. На Windows — Job Object с
  `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, иначе остаются осиротевшие `node`/`python`.

### Streamable HTTP (этап 2)

- `POST` JSON-RPC на `url`, ответ может быть однострочным JSON или потоком SSE.
- Учитывать защиту от DNS-rebinding на стороне сервера: cognee по умолчанию отвечает
  `421 Misdirected Request`, если `Host` не в списке (`MCP_ALLOWED_HOSTS`) — в UI это должно
  выглядеть понятным текстом, а не «сервер сломан».
- Наши правила SSRF (`internal/netx/ssrf.go`) применяем и к адресу сервера, и к редиректам:
  запрет `169.254.169.254` (metadata), приватных диапазонов — если адрес не задан явно
  локальным (`127.0.0.1`, `localhost`, `host.docker.internal`).
- Заголовки авторизации — из keychain, никогда из `settings.json`.

### SSE (этап 3)

Устаревающий, но жив у части серверов. Подключать после HTTP, как совместимость.

## 6. Три примера, на которых проверяем дизайн

### 6.1. Google Maps (`modelcontextprotocol/servers-archived`, stdio)

| Параметр | Значение |
|---|---|
| Запуск | `npx -y @modelcontextprotocol/server-google-maps` (или Docker-образ, но `-i` обязателен) |
| Секрет | `GOOGLE_MAPS_API_KEY` в env |
| Инструментов | 7: `maps_geocode`, `maps_reverse_geocode`, `maps_search_places`, `maps_place_details`, `maps_distance_matrix`, `maps_elevation`, `maps_directions` |
| Аннотации | в README не заявлены → считаем «неизвестно», подтверждение по умолчанию |
| Результаты | компактный JSON, хорошо ложится в `compact.go` |

Что проверяет в нашем дизайне: env-ключ, «7 инструментов, схемы небольшие» (можно включать все),
отсутствие аннотаций → консервативный режим подтверждений. Идеальный первый тестовый сервер.

### 6.2. Playwright MCP (`microsoft/playwright-mcp`, stdio)

| Параметр | Значение |
|---|---|
| Запуск | `npx @playwright/mcp@latest`, Node 18+ |
| Секрет | не требуется (браузер на машине) |
| Инструментов | десятки (навигация, снапшоты доступности, клики, формы, вкладки, сеть) |
| Аргументы сервера | важны: `--allowed-hosts`, `--headless`, профиль браузера, `--timeout` |
| Результаты | accessibility-снапшот = большой структурированный текст; возможны изображения |

Что проверяет: **контекстный бюджет** (в промпте нельзя держать весь набор), `args` как часть
конфига, подтверждения для «пишущего» действия (клик по кнопке оплаты). В README сам Microsoft
отмечает, что для кодинг-агентов CLI-вариант дешевле по токенам, а MCP оправдан, когда нужен
живой браузерный контекст. Для нас это аргумент за «включать инструменты поштучно».

### 6.3. cognee-mcp (`topoteretes/cognee`, stdio + HTTP + SSE)

| Параметр | Значение |
|---|---|
| Запуск | `uv sync` + `python src/server.py [--transport http --host 127.0.0.1 --port 8000 --path /mcp]`, либо Docker `cognee/cognee-mcp:main` |
| Секреты | `LLM_API_KEY` (по умолчанию OpenAI), опционально `API_URL`/`API_TOKEN` в API-режиме |
| Инструментов | минимальный memory API: `remember`, `recall`, `forget` |
| Особенности | session-память + граф памяти; автономный `sampling`-режим (`LLM_PROVIDER=mcp-sampling`) — сервер просит модель у **хоста**; защита Host/Origin (`MCP_ALLOWED_HOSTS`, `MCP_DISABLE_DNS_REBINDING_PROTECTION`) |

Что проверяет: Python-окружение пользователя (`uv`), долгий первый запуск (нужно показывать
«запускается…» и не считать это зависанием), HTTP-транспорт, а также вопрос про `sampling` (§9).

## 7. Безопасность

1. **stdio = запуск произвольной команды.** Первый запуск сервера показываем диалогом:
   «будет выполнено: `npx -y @playwright/mcp@latest` в папке …» + галочка «я понимаю, что это
   сторонний код с доступом к моим файлам и сети».
2. **Окружение фильтруем.** Сервер получает только: `PATH`, системные `HOME`/`TMPDIR`/локаль и
   те переменные, что перечислены в карточке. Наши ключи провайдеров (`DEEPSEEK_API_KEY`,
   `OPENROUTER_API_KEY`, `ZAI_*`) в сервер не уходят никогда.
3. **Подтверждения по аннотациям.** `readOnlyHint: true` → без подтверждения; неизвестно или
   `destructiveHint: true` → спрашиваем, как сейчас спрашиваем перед `run_terminal`. Галочка
   «не спрашивать для этого инструмента» — отдельная, по инструменту.
4. **Сеть.** HTTP-транспорт через наши SSRF-правила; логи сервера — через `internal/redact`
   (в них легко утекают токены).
5. **Ограничения по объёму.** Жёсткий лимит на размер одного ответа и на суммарный объём за ход;
   превышение — усечение с пометкой, а не падение.
6. **Изоляция настроек.** MCP-серверы не могут менять наши настройки, секреты и правила; это
   только поставщики инструментов.

## 8. UI (Settings → MCP)

```
┌ MCP-серверы ────────────────────────────────────────────────┐
│ [ + Добавить ]  [ Импорт JSON ]        включено 2 из 5       │
│                                                             │
│ ✓ Google Maps      stdio  ● работает · 7 инструментов        │
│   Включено: 3 из 7 (maps_geocode, maps_search_places, …)     │
│   [Проверить] [Перезапустить] [Логи] [Изменить] [Удалить]    │
│                                                             │
│ ○ Playwright       stdio  ○ выключен · 27 инструментов       │
│   Схемы ≈ 6.5k токенов — включайте только нужное             │
│                                                             │
│ ! cognee           http   ✕ ошибка: 421 Misdirected Request  │
│   Подсказка: сервер проверяет Host — добавьте MCP_ALLOWED_HOSTS│
└─────────────────────────────────────────────────────────────┘
```

Элементы, без которых фича бесполезна (по опыту любых интеграций):

- **«Проверить»** — `initialize` + `tools/list`, показывает список инструментов, версию
  протокола и текст ошибки. Без этого пользователь не понимает, почему агент «не видит» сервер.
- **Статус** (выключен / запускается / работает / ошибка) и **логи** сервера построчно.
- **Чек-лист инструментов** с оценкой токенов.
- **Импорт/экспорт JSON** в формате `mcpServers`.
- Понятные ошибки: «npx не найден», «нет ключа GOOGLE_MAPS_API_KEY», `421`/`403` от HTTP-сервера.

## 9. Открытые вопросы

1. **`sampling`.** Сервер (пример — cognee) может попросить у клиента генерацию. У нас есть свои
   провайдеры и учёт стоимости — значит либо не поддерживаем в MVP, либо отвечаем только
   выбранной «дешёвой» моделью и с явным согласием пользователя. Иначе — неожиданные траты.
2. **OAuth для HTTP.** Часть удалённых серверов требует OAuth (не Bearer). Отложено.
3. **Песочница.** Сейчас сторонний сервер получает доступ ко всему, что доступно приложению.
   Варианты: sandbox-exec/AppContainer, запуск только из доверенных путей, предупреждение.
4. **Свои MCP-серверы для себя.** Мы можем выставить наши инструменты наружу как MCP-сервер —
   тогда NotCursor смогут использовать другие клиенты. Полезно, но отдельная задача.
5. **`roots`.** Передавать серверу корень проекта (чтобы браузерный сервер видел наши файлы) —
   удобно, но расширяет доступ; только по явному согласию на проект.

## 10. Этапы

| Этап | Объём | Результат |
|---|---|---|
| **MVP** | stdio, карточки серверов, `initialize`/`tools/list`/`tools/call`, чек-лист инструментов, префиксы, таймауты, логи, подтверждения | Можно подключить google-maps и убедиться, что модель вызывает его инструменты |
| 2 | Streamable HTTP, импорт/экспорт JSON, области (чат/проект), оценка токенов, `progress` в живую строку | Playwright и cognee по HTTP |
| 3 | SSE, `resources`, `prompts`, per-tool «не спрашивать», Windows Job Object + повторные запуски | Взрослое поведение как в Claude Desktop |
| 4 | OAuth, `sampling`, `roots`, песочница, сервисный MCP наружу | Произвольные удалённые серверы |

Оценка: MVP — ориентировочно **2–4 дня** с тестами и UI; этап 2 — **3–5 дней**; дальше по мере
надобности. Стоимость поддержки растёт с числом транспортов, поэтому SSE и OAuth — последними.

## 11. Тесты (что проверяем, а не «покрытие»)

- JSON-RPC: сборка/разбор строк, ответ на неизвестный `id`, ошибки `-32601`.
- `tools/list` → корректные `ToolSpec` (имена с префиксом, описания, схема без искажений).
- Фильтр окружения: наши `*_API_KEY` не попадают в дочерний процесс (тест на подставном сервере).
- Таймауты и хард-килл: подставной сервер молчит → статус «ошибка», процесс не остаётся жив.
- Дедупликация имён и превышение лимита включённых инструментов → предупреждение.
- Усечение больших результатов и `isError: true`.
- Интеграционный тест: наш тестовый MCP-сервер на Go (stdio) в `internal/mcp/testdata`.
