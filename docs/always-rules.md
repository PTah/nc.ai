# Гигиена always-правил

Правило с `alwaysApply: true` уезжает в **каждый** запрос: оно занимает контекст молча, до того как
пользователь что-то напечатал, и оплачивается токенами на каждом шаге. Здесь — как держать этот
бюджет под контролем. Речь про правила агента (`.cursor/rules/*.mdc`), не про системный промпт
NotCursor.

## Что кладём в always, а что нет

| В always (`alwaysApply: true`) | В правило по требованию (`alwaysApply: false` + `description`) |
|---|---|
| Язык ответа, обращение, краткость | Схема конкретного проекта: хосты, деплой, remotes |
| Git-дисциплина: не коммитить без просьбы, conventional commits | Порядок релиза, нотаризация, подпись |
| Безопасность: секреты, `.cursor/` в git, бэкап перед правкой конфигов | Разбор конкретного протокола/провайдера |
| Кодировки и переносы строк | Чек-листы по одному сервису (MikroTik, HAProxy) |
| Имена/пути инструментов, которые агент трогает каждый день | Узкие рецепты «как сделать X в этом репо» |

Правило: **always — только то, что нужно на каждом шаге любой задачи**. Всё «иногда» уходит в
правило с `description` — его подтянут по смыслу.

## Бюджет

- 10–15 always-правил по 1–3 КБ — уже ~20 тыс. символов в каждом запросе. Это заметные деньги на
  длинных прогонах.
- Ориентир: суммарно always ≤ 40–60 КБ. Выше — резать или переносить в «по требованию».
- Проверка перед добавлением: «если я уберу это правило, агент сломает задачу в 1 случае из 5?» Если
  нет — это не always.

## Признаки, что пора чистить

1. Правило дублирует другое (две записи про коммиты — типичный случай).
2. Правило описывает процесс, а не ограничение: «сначала подумай, потом делай» ничего не меняет.
3. Правило про один проект лежит в глобальных — ему место в `*-ops.mdc` проекта.
4. Текст разросся: заголовки, примеры, история изменений — оставить 5–10 строк сути.
5. Есть `.bak-*`/`*.old` копии правил в каталоге: они не применяются, но засоряют чтение — удалить.

## Как чистить

```bash
# размер always-правил (Windows PowerShell)
Get-ChildItem .cursor/rules/*.mdc | ForEach-Object {
  $always = Select-String -Path $_.FullName -Pattern 'alwaysApply:\s*true' -Quiet
  if ($always) { "{0,7} {1}" -f $_.Length, $_.Name }
} | Sort-Object -Descending
```

Дальше:

- дубли — слить в одно;
- проектное — вынести в `.cursor/rules/<repo>-ops.mdc` (см. `propose-project-ops`);
- лишние примеры — в `docs/`, в правиле оставить ссылку;
- `*.bak-*` — удалить (история есть в git).

## Связь с NotCursor

- Системный промпт самого приложения уже держит краткость и MCP-first, поэтому не надо дублировать
  это правилом.
- Память проекта (`remember` / `recall`) — не замена правилам: факты живут в `docs/`, а правило —
  это ограничение на поведение агента.
- Файлы `.cursor/` в git не попадают (`no-cursor-in-repositories`): всегда-правила — локальная
  гигиена машины, а не часть продукта.
