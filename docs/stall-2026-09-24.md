# Разбор: шаг «застыл» на 12 минут без предупреждения (24.09.2026)

Короткий отчёт о случае, когда прогон агента не подавал признаков жизни больше
десяти минут, хотя watchdog должен был предупредить на десятой. Файл нужен, чтобы
симптом не потерялся: причины оказались неочевидными, и часть из них —
инфраструктурные (наш собственный таймаут и перезапуск клиента).

## Что наблюдалось

- Прогон стартовал в 19:35:24, следующий выбор модели в логе — только в 19:48:51:
  тринадцать минут тишины.
- В чате при этом были записи об обрывах связи с провайдером:

```
Соединение с LLM потеряно (Post "https://api.deepseek.com/chat/completions":
  read tcp 192.168.1.10:55835->3.173.21.63:443: …)
Соединение с LLM потеряно (stream read: read tcp …: connection reset by peer)
⟳ Приложение перезапущено после обновления 0.6.33 → 0.7.2.
```

- Сообщений watchdog не нашлось **ни в одном** чате — поиск по всем файлам
  `~/Library/Application Support/NotCursor/chats/*.json` ничего не дал.

## Где смотреть при повторе

```bash
# что делал агент: выбор модели, старт/предупреждение/обрыв watchdog, отброшенные события
tail -50 "$HOME/Library/Application Support/NotCursor/agent.log"

# идёт ли прогон прямо сейчас (этот файл читает и build.sh)
cat "$HOME/Library/Application Support/NotCursor/running.json"

# записи прогона в чате: обрывы, повторы, разборы затыка
python3 -c "import json,glob;f=sorted(glob.glob('$HOME/Library/Application Support/NotCursor/chats/*.json'))[-1];d=json.load(open(f));print([i.get('content','')[:80] for s in d.get('sessions',[]) for i in json.loads(s.get('itemsJson','[]')) if i.get('kind')=='system'][-8:])"
```

## Три причины

1. **Живое, но замолчавшее соединение висело бесконечно.** У облачных провайдеров
   стоял общий `http.Client{Timeout: 180s}` (`internal/llm/providers/deepseek/client.go:44`
   и аналоги), а стрим читался `bufio.Scanner` без дедлайна: если TCP не разорван,
   но данных нет, `Scan()` ждёт до keepalive. Никакой таймаут (180 с) на стрим не
   действовал, потому что `llm.StreamClient` общий `Timeout` снимает
   (`internal/llm/openai_stream.go`).
2. **Watchdog не оставлял следов и мог не сработать.** В `watchStall` сначала шёл
   `emit(Event{notice})`, и только потом `cancel()`. Сам `emit` начинается с
   `if !stillCurrent() { return }`: события устаревшего прогона молча
   выбрасывались. Плюс сторож вообще не писал в `agent.log`, поэтому отличить
   «не сработал» от «сработал, но проглотили» было невозможно.
3. **Перезапуск клиента поверх активного прогона.** Обновление применялось через
   `quit` + `open`, прогон при этом умирал мгновенно, а ожидание продолжалось над
   уже мёртвым процессом. Это прямая ошибка в процессе обновления, не в модели.

## Что исправлено (0.7.3)

| Причина | Правка |
|---|---|
| Висящий стрим | `StreamIdleTimeout = 120s` в `internal/llm/openai_stream.go`: чтение идёт в горутине, основной цикл ждёт с таймером и возвращает «провайдер молчит 2 мин». Тесты — `internal/llm/openai_stream_test.go` |
| Watchdog без следов | `cancel()` **до** `emit()`; логи `stall start` / `stall warn` / `stall fired` / `stall canceled` в `agent.log`; логгер проброшен из `app.go` (`Runner.Logf`) |
| Проглоченная диагностика | `notice` / `error` / `reconnect` при устаревшем прогоне пишутся в лог как `dropped … (устаревший прогон) session=…` |
| Ретраи не считались жизнью | `stallTouch("повтор после сетевой ошибки")` на каждом повторе + общий лимит серии `retryBudget = 3 мин` (`internal/agent/agent.go`) |
| Предупреждение только на 10-й минуте | `stallWatch.warning()` — предупреждение на половине лимита: «⏳ Шаг N молчит 5 мин (фаза: жду ответ модели)… прерву через 5 мин» |
| Перезапуск поверх прогона | Приложение пишет `running.json`, пока идёт прогон (`App.markRunStart/markRunEnd`, сиротский маркер снимается на старте). `build.sh` перед `quit` останавливается с подсказкой; перезапуск возможен только с `--force-restart` |

## Как проверить, что работает

```bash
# 1. прогон идёт — маркер есть
cat "$HOME/Library/Application Support/NotCursor/running.json"

# 2. сборка больше не перезапускает клиент поверх работы
./build.sh --no-restart          # обычная сборка: рестарта нет вообще
./build.sh                       # если прогон активен — откажется перезапускать
./build.sh --force-restart       # осознанный перезапуск, обрывающий прогон

# 3. в логе видно работу сторожа
grep -E 'stall (start|warn|fired|canceled)' "$HOME/Library/Application Support/NotCursor/agent.log"
```

## Что осталось на будущее

- Проверить, как ведёт себя `retryBudget` на медленных, но живых провайдерах
  (например, Local с большим контекстом): 3 минуты суммарных повторов — оценка,
  не измерение.
- Если провайдер умеет присылать SSE-комментарии (`: ping`) как keep-alive,
  их стоит учитывать как признак жизни, не сбрасывая idle-таймер на пустых
  данных: сейчас пустые чанки намеренно не считаются активностью.
