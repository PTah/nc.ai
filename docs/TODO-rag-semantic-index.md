# ToDo: semantic index / RAG (phase 7)

**Только private remotes (`home`, `kalinamall`). На `github` эти ToDo не пушим.**

Статус: **отложено** — glob + grep + project map закрывают текущие репо; индекс не окупается.

## Почему не сейчас

NotCursor — лёгкий локальный агент. Semantic search из Cursor/Windsurf тянет эмбеддинги, watch, SQLite и отдельный индекс. На наших размерах репо `glob`/`grep`/`find_files` + тёплое дерево уже находят символ за 1–2 шага. RAG без метрик качества только жрёт RAM/диск и путает агента скрытым контекстом. Вернёмся, когда типичный запрос станет «где авторизация?» без имени символа и grep начнёт промахиваться.

## Что это

Фоновый семантический индекс репозитория:

1. Скан файлов при `OpenProject` (и watch на изменения).
2. Нарезка на чанки (функции/классы — желательно Tree-sitter; можно начать с окон по N строк).
3. Эмбеддинги → локальный store (SQLite / in-memory).
4. При запросе пользователя: top-K чанков **опционально** подмешиваются в контекст или отдаются отдельным tool `semantic_search`.

## Для чего

Когда **find_files + grep + project_map** уже не хватает на огромных репо («где авторизация?» без точного символа). Экономит шаги tools и токены на «блуждание».

## Когда браться

- Hit% и качество агента упираются в поиск по подстроке.
- Типичные задачи пользователя — «семантические», не `grep FooBar`.
- Есть ресурс на индекс/watch/обновление без тормозов UI.

## Чего не делать сразу

- Не заменять tools скрытым RAG без метрик.
- Не тащить тяжёлый cloud embedding API без явной настройки.
